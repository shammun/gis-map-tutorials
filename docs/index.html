Glow-dot time-lapse with a mirrored season chart

The storm belts follow the sun

Every 6-hourly position of every tropical cyclone of 1990-2024 is one small dot of light, drawn on its day of the year. Where many storms passed, the dots add up and the map glows. Read it like a long-exposure photograph: brightness is mostly how often storms passed there (stronger storms glow a little more). The chart under the map counts the storms in progress, Northern Hemisphere upwards and Southern downwards; in the video its playhead shows the date.

Steps to make it

  1. Load the storm positions (34 knots or more, 6-hourly, all basins): data/gis_styles/cyclones.npz, or rebuild it from NOAA's files.
  2. Build one Equal Earth pixel grid centred on 165°W, so the cut falls on Africa and no storm basin is split.
  3. Bin the positions into pixels and blur them twice (a sharp core and a soft halo); weight each by its wind and by its age.
  4. Tone-map the sum with 1 − exp(−gain · v) and colour it from dark red to white on the dark base map.
  5. Count the storms in progress per calendar day for the two hemispheres and draw the mirrored chart.
  6. Add the title, the month and the credits; save the poster (all days at once).
  7. For the video, draw one frame per half day with a five-day fading tail, and encode the frames with ffmpeg.

# %% [markdown]
# # 1 · Glow-dot time-lapse with a mirrored season chart
#
# **The idea.** Put every event on a dark map as a tiny dot of light and *add* the light where dots fall on top of
# each other. Places with many events glow; places with few stay dark. Then run a clock through the calendar and
# show only the events near "today", and put a small mirrored chart under the map (one group up, the other down)
# with a playhead. The map says *where*, the chart says *when*, and they move together.
#
# **This map.** Thirty-five years of tropical cyclones (IBTrACS, 1990-2024), each 6-hourly position drawn on
# its day of the year. The Northern Hemisphere season and the Southern one light up in turn, half a year apart.
#
# Steps: 1 data → 2 one map grid → 3 additive glow → 4 tone-mapping and colour → 5 the mirrored chart →
# 6 the finished frame → 7 the animation.

# %% [markdown]
# ## Settings
# Everything you may want to change is in this one cell. The checks at the bottom **stop** the notebook with a plain
# message if a setting cannot work, before anything slow starts.
#
# `MODE = "FAST"` (the default, one to three minutes; right for Google Colab) writes the poster at 1920 × 1080 px and a short
# preview clip of the animation at 960 × 540 px. `MODE = "FULL"` writes the poster at 3840 × 2160 px and the whole
# animation at 1920 × 1080 px (several minutes).

# %%
import os
import sys

MODE = "FULL" if "--full" in sys.argv else os.environ.get("GIS_MODE", "FAST")   # "FAST" (preview) or "FULL" (poster size, whole animation)
OUT_DIR = os.environ.get("GIS_OUT", "")          # output folder; "" = /content/out on Google Colab, ./out anywhere else
SAMPLE_DAY = 250                                 # the calendar day drawn in steps 3-4: 0 = 1 January ... 364; 250 = 8 September

from gismaps import nb                           # helpers: data loader, show(), video(), STOP checks, PASS / FAIL

nb.stop_unless(MODE in ("FAST", "FULL"), f"MODE = {MODE!r} must be FAST or FULL")
nb.stop_unless(0 <= SAMPLE_DAY <= 364, f"SAMPLE_DAY = {SAMPLE_DAY} must be a day of the year, 0 to 364")
POSTER_SCALE = 1.0 if MODE == "FAST" else 2.0    # the design size is 1920 x 1080; the poster is saved at this multiple
OUT = nb.out_dir(OUT_DIR)
print(f"settings OK | mode: {MODE} | output folder: {OUT} | poster {int(1920 * POSTER_SCALE)} x {int(1080 * POSTER_SCALE)} px")

# %% [markdown]
# ## 1 · The data
# One small file: every 6-hourly position of every tropical cyclone of 1990-2024 at tropical-storm strength or
# more (IBTrACS v04r01, NOAA NCEI, public domain). `nb.load` reads it from `data/gis_styles/`, downloads it if it is
# missing, and rebuilds it from NOAA's files if that fails (`gismaps/prepare_data.py` is the record of how).
# %%
import numpy as np
import matplotlib.pyplot as plt

from gismaps.styles import common as C, glow      # the map-style code of this repository

data = nb.load("cyclones")                  # lat, lon, wind_kt, doy (0-based day of year), year
print({k: (v.shape, v.dtype) for k, v in data.items() if v.ndim})
print("fixes:", len(data["lat"]), "| years", data["year"].min(), "to", data["year"].max())

# %% [markdown]
# ## 2 · One projection, one pixel grid
# Everything on the map (land, dots) is placed on the **same pixel grid**. `MapGrid` holds a PROJ string and an
# extent; `xy(lon, lat)` gives pixel positions. Equal Earth is an equal-area projection, so the same number of storms
# makes the same amount of light anywhere. We centre it on 165°W: the cut then falls on Africa (15°E), where
# there are no tropical cyclones, and no ocean basin is split.

# %%
grid = C.MapGrid.from_box("+proj=eqearth +lon_0=-165", 15.001, 374.999, -47, 53, w=1840)
x, y = grid.xy(data["lon"], data["lat"])
points = np.c_[x, y]
print("map is", grid.w, "x", grid.h, "px;", round(grid.mpp / 1000, 1), "km per pixel")

# %% [markdown]
# ## 3 · Additive glow
# `C.glow` bins the points into pixels and blurs the result twice: a sharp core (1 px) and a soft halo (5 px).
# Nothing is "drawn": the image is a **sum**, so density becomes brightness by itself.
#
# For one calendar day we give each fix a weight that fades with its age: today 1, five days ago 1/e. The fading
# tail turns separate 6-hourly fixes into short comet tracks.

# %%
day = SAMPLE_DAY                                         # 8 September with the default setting
age = (day - data["doy"]) % 365                         # days since each fix, round the calendar
near = age < 25
weight = np.clip(data["wind_kt"][near] / 64.0, 0.5, 2.2) * np.exp(-age[near] / 5.0)   # stronger storms glow more
buf = C.glow(points[near], weight, (grid.h, grid.w))
print("buffer max", round(float(buf.max()), 2), "| pixels lit", int((buf > 0.05).sum()))

# %% [markdown]
# ## 4 · Tone-mapping and colour
# The buffer has no upper limit, so it is squeezed into 0..1 with `1 - exp(-gain * v)` (bright places saturate
# gently instead of clipping) and coloured with a ramp that only gets lighter: dark red → orange → amber → white.
# Opacity rises faster than colour, so even a single faint dot is visible on the dark ground.

# %%
land = grid.land("110m")                                # Natural Earth land through a lat/lon raster
base = C.over(np.broadcast_to(C.rgb("#080b14"), (grid.h, grid.w, 3)).copy(), C.rgb("#161c2c"), land)
img = glow.glow_rgb(base, buf, gain=1.7)

fig, axs = plt.subplots(1, 2, figsize=(14, 2.9), facecolor="#05070d")
axs[0].imshow(C.tone(buf, 1.7), cmap="gray"); axs[0].set_title("tone-mapped buffer", color="w")
axs[1].imshow(img); axs[1].set_title("on the base map, 8 September", color="w")
for a in axs:
    a.axis("off")
plt.tight_layout(); plt.show()

# %% [markdown]
# ## 5 · The mirrored season chart
# For the chart we count how many storms are in progress on each calendar day, on average: fixes per day ÷ 4
# (four fixes a day) ÷ 35 years, for the Northern Hemisphere (drawn upwards) and the Southern (downwards).

# %%
north, south = glow.season_counts(data["doy"], data["lat"] > 0, n_years=35)
print("north peaks on day", int(north.argmax()), f"({north.max():.1f} storms at once);",
      "south peaks on day", int(south.argmax()), f"({south.max():.1f})")

# %% [markdown]
# ## 6 · The finished frame, and the whole year as a poster
# `glow.StormSeason` wraps steps 2-5 with the map furniture (title, month, chart, credits).

# %%
storm = glow.StormSeason(data)
storm.frame(250.0, OUT / "01_glow_sep.png")
storm.frame(45.0, OUT / "01_glow_feb.png")
nb.strip([OUT / "01_glow_feb.png", OUT / "01_glow_sep.png"])

# %%
poster = storm.poster(OUT / "glow_season.png", scale=POSTER_SCALE)      # all days at once, 3840 x 2160
nb.show(poster)

# %% [markdown]
# ## 7 · The animation
# Half a day per frame at 30 frames a second: the year takes 24 seconds. `MODE = "FULL"` in the settings cell (or
# `--full` after the script name) renders all of it; `"FAST"` makes a short preview with the same code. Frames are written as PNG and encoded with ffmpeg.

# %%
if MODE == "FULL":                               # the whole animation, 1920 x 1080 px
    movie = storm.animate(OUT / "glow_season.mp4", OUT / "frames_01")
else:                                            # a short preview: every 16th frame, 960 x 540 px, 12 frames a second
    movie = C.preview(storm.animate, OUT / "glow_season_preview.mp4", OUT / "frames_01", thin=16)
nb.video(movie)

# %% [markdown]
# ## Check the outputs
# The last cell checks that every output exists and is what it should be, and prints PASS or FAIL per check.

# %%
size = (int(1920 * POSTER_SCALE), int(1080 * POSTER_SCALE))
checks = [
    ("the poster exists", poster.exists()),
    (f"the poster is {size[0]} x {size[1]} px", nb.image_size(poster) == size),
    ("two sample frames, 1920 x 1080 px", all(nb.image_size(OUT / f) == (1920, 1080) for f in ("01_glow_feb.png", "01_glow_sep.png"))),
    ("more than 50,000 storm positions were read", len(data["lat"]) > 50_000),
    ("the northern season peaks in August-October, the southern in January-March", 212 <= int(north.argmax()) <= 304 and int(south.argmax()) <= 90),
]
if not os.environ.get("GIS_PART"):               # (GIS_PART marks a frame worker of the parallel FULL render)
    checks.append(("the movie exists and is not empty", movie is not None and movie.exists() and movie.stat().st_size > 20_000))
nb.verify(checks)

# %% [markdown]
# ## Download (Google Colab)
# On Colab this zips the pictures and movies of the output folder and offers them as one download; anywhere else it
# only says where they are.

# %%
nb.download(OUT)

Epoch-stacked footprints

Storm Ciarán's footprint

Each coloured shape is the area where sea-level pressure was below 960 hPa at one moment, every three hours on 1-2 November 2023. The shapes are stacked with the newest on top, so the crescents left showing are places the deep core of the storm has already left. Follow the colours from purple to yellow to follow time; the white line is the path of the lowest pressure, and the legend gives that pressure at each step.

Steps to make it

  1. Load the hourly sea-level pressure of 1-2 November 2023: data/gis_styles/ciaran.npz, or rebuild it from ARCO-ERA5.
  2. Follow the low from a seed point, hour by hour (the minimum of the whole box would jump to another low).
  3. Every three hours, keep the connected area below 960 hPa that holds the tracked centre.
  4. Resample the pressure to a Lambert conformal pixel grid and apply the threshold there, for smooth edges.
  5. Give the epochs ordered plasma colours and stack them, oldest first, on the dark base map.
  6. Add the track, the legend with the lowest pressure of each step, the scale bar and the credits; save the poster.
  7. For the video, show each epoch alone with its outline, then build the stack, and encode with ffmpeg.

# %% [markdown]
# # 2 · Epoch-stacked footprints
#
# **The idea.** Take the outline of one thing at several times and give each time one colour of an ordered ramp.
# First show each epoch alone. Then stack them, oldest at the bottom and newest on top: wherever only an *older*
# epoch reached, its colour stays visible as a crescent. One still picture then holds the whole history of a moving
# or shrinking shape.
#
# **This map.** Storm Ciarán, 1-2 November 2023: the area where mean-sea-level pressure was below 960 hPa,
# every 3 hours (ERA5).
#
# Steps: 1 data → 2 follow the low → 3 one footprint per epoch → 4 smooth edges on the map grid →
# 5 ordered colours and the stack → 6 the finished frames → 7 the animation.

# %% [markdown]
# ## Settings
# Everything you may want to change is in this one cell. The checks at the bottom **stop** the notebook with a plain
# message if a setting cannot work, before anything slow starts.
#
# `MODE = "FAST"` (the default, one to three minutes; right for Google Colab) writes the poster at 1920 × 1080 px and a short
# preview clip of the animation at 960 × 540 px. `MODE = "FULL"` writes the poster at 3840 × 2160 px and the whole
# animation at 1920 × 1080 px (several minutes).

# %%
import os
import sys

MODE = "FULL" if "--full" in sys.argv else os.environ.get("GIS_MODE", "FAST")   # "FAST" (preview) or "FULL" (poster size, whole animation)
OUT_DIR = os.environ.get("GIS_OUT", "")          # output folder; "" = /content/out on Google Colab, ./out anywhere else
THRESHOLD_HPA = 960.0                            # the footprint: sea-level pressure below this value (hPa)
STEP_HOURS = 3                                   # one footprint every this many hours

from gismaps import nb                           # helpers: data loader, show(), video(), STOP checks, PASS / FAIL

nb.stop_unless(MODE in ("FAST", "FULL"), f"MODE = {MODE!r} must be FAST or FULL")
nb.stop_unless(955 <= THRESHOLD_HPA <= 1000, f"THRESHOLD_HPA = {THRESHOLD_HPA}: Ciarán's centre fell to about 953 hPa; use 955 to 1000")
nb.stop_unless(STEP_HOURS in (1, 2, 3, 4, 6), "STEP_HOURS must be 1, 2, 3, 4 or 6")
POSTER_SCALE = 1.0 if MODE == "FAST" else 2.0    # the design size is 1920 x 1080; the poster is saved at this multiple
OUT = nb.out_dir(OUT_DIR)
print(f"settings OK | mode: {MODE} | output folder: {OUT} | poster {int(1920 * POSTER_SCALE)} x {int(1080 * POSTER_SCALE)} px")

# %% [markdown]
# ## 1 · The data
# Hourly ERA5 sea-level pressure and 10-m wind for 1-2 November 2023 over the north-east Atlantic and western
# Europe (Copernicus Climate Change Service / ECMWF), reduced to one small file.
# %%
import numpy as np
import matplotlib.pyplot as plt

from gismaps.styles import common as C, epochs      # the map-style code of this repository

data = nb.load("ciaran")                    # hourly ERA5: msl_hpa10 (hPa x 10), u10_cms, v10_cms on lat/lon
p = data["msl_hpa10"] / 10.0                    # hPa, shape (48 hours, lat, lon)
lat, lon, time = data["lat"], data["lon"], [str(t) for t in data["time"]]
print(p.shape, time[0], "to", time[-1], "| lowest pressure in the box:", p.min(), "hPa")

# %% [markdown]
# ## 2 · Follow the low (never "the minimum of the box")
# Two lows are in this box: Ciarán and its older, larger parent low near Iceland. The minimum of the whole box
# jumps between them. So we **seed** the tracker where Ciarán was at 12 UTC on 1 November (48°N, 17°W) and
# then, hour by hour, take the lowest pressure within 8 grid cells (2°) of the previous position.

# %%
i0 = time.index("2023-11-01T12")
seed = (int(np.argmin(np.abs(lat - 48.0))), int(np.argmin(np.abs(lon + 17.0))))
rc = epochs.track_minimum(p, seed, i0, radius=8)
for i in range(i0, 48, 6):
    print(time[i], f"{lat[rc[i, 0]]:5.2f}N {lon[rc[i, 1]]:6.2f}E  {p[i, rc[i, 0], rc[i, 1]]:.1f} hPa")

# %% [markdown]
# ## 3 · One footprint per epoch
# The footprint is the **connected** region below the threshold that contains the tracked centre
# (`scipy.ndimage.label`), so the parent low never leaks in. We pick 960 hPa: inside this box the parent low stayed above
# 964 hPa, and Ciarán was below 960 hPa from the evening of 1 November to the evening of 2 November.

# %%
steps = list(range(time.index("2023-11-01T21"), time.index("2023-11-02T21") + 1, STEP_HOURS))
masks = [epochs.footprint(p[i], THRESHOLD_HPA, tuple(rc[i])) for i in steps]
cell_km2 = (111.195 * 0.25) ** 2 * np.cos(np.deg2rad(lat))[:, None]        # area of one 0.25-degree cell
for i, m in zip(steps, masks):
    print(time[i], f"area below {THRESHOLD_HPA:.0f} hPa: {float((m * cell_km2).sum()) / 1e3:6.0f} thousand km2")

# %% [markdown]
# ## 4 · Smooth edges on the map grid
# A 0.25° mask drawn on a map has stairs. Instead we resample the **pressure** to the map's pixels (cubic) and
# apply the threshold there. The map is a Lambert conformal conic (standard parallels 45°N and 58°N), the usual
# choice for a mid-latitude weather map.

# %%
grid = C.MapGrid.fit("+proj=lcc +lat_1=45 +lat_2=58 +lat_0=52 +lon_0=-3.5", -60e3, 30e3, 2050e3, 1240, 1000)
i = steps[3]
p_px = grid.sample(p[i], lat, lon, order=3)
alpha = np.clip((THRESHOLD_HPA - p_px) / 0.15 + 0.5, 0, 1)        # 1 inside, 0 outside, a 1-pixel soft edge
fig, axs = plt.subplots(1, 2, figsize=(11, 4.4))
axs[0].imshow(masks[3][::-1], cmap="gray"); axs[0].set_title("mask on the 0.25° grid")
axs[1].imshow(alpha, cmap="gray"); axs[1].set_title("threshold applied on the map pixels")
for a in axs:
    a.axis("off")
plt.tight_layout(); plt.show()

# %% [markdown]
# ## 5 · Ordered colours, then the stack
# The colours come from one perceptually ordered ramp (`plasma`), first = oldest. An ordered ramp matters: the
# reader must be able to sort the epochs by colour alone. `epochs.stack` lays the footprints oldest first.

# %%
ciaran = epochs.CiaranFootprint(data, threshold=THRESHOLD_HPA, step=STEP_HOURS)           # does steps 2-4 for every epoch and builds the base map
cols = epochs.epoch_colours(len(ciaran.idx))
img = epochs.stack(ciaran.base, ciaran.alphas, cols, upto=len(cols))
plt.figure(figsize=(9, 7.3)); plt.imshow(img); plt.axis("off"); plt.show()

# %% [markdown]
# ## 6 · The finished frames
# Two kinds of frame: **solo** (one epoch filled, with that hour's isobars, earlier ones as outlines) and the
# **stack**. The legend is the clock: it lists every epoch with the lowest pressure at that time.

# %%
ciaran.frame(OUT / "02_solo.png", upto=4, solo=3)
poster = ciaran.poster(OUT / "epoch_footprints.png", scale=POSTER_SCALE)
nb.show(OUT / "02_solo.png")
nb.show(poster)

# %% [markdown]
# ## 7 · The animation
# Each epoch alone for about a second, then the stack builds, then a hold.

# %%
if MODE == "FULL":                               # the whole animation, 1920 x 1080 px
    movie = ciaran.animate(OUT / "epoch_footprints.mp4", OUT / "frames_02")
else:                                            # a short preview: every frame, 960 x 540 px, 12 frames a second
    movie = C.preview(ciaran.animate, OUT / "epoch_footprints_preview.mp4", OUT / "frames_02", thin=1)
nb.video(movie)

# %% [markdown]
# ## Check the outputs
# The last cell checks that every output exists and is what it should be, and prints PASS or FAIL per check.

# %%
size = (int(1920 * POSTER_SCALE), int(1080 * POSTER_SCALE))
checks = [
    ("the poster exists", poster.exists()),
    (f"the poster is {size[0]} x {size[1]} px", nb.image_size(poster) == size),
    ("the sample frame exists", (OUT / "02_solo.png").exists()),
    ("the tracked low deepens below the threshold", float(min(p[i, rc[i, 0], rc[i, 1]] for i in steps)) < THRESHOLD_HPA),
    ("at least three footprints are stacked", len(ciaran.idx) >= 3),
]
if not os.environ.get("GIS_PART"):               # (GIS_PART marks a frame worker of the parallel FULL render)
    checks.append(("the movie exists and is not empty", movie is not None and movie.exists() and movie.stat().st_size > 20_000))
nb.verify(checks)

# ## Download (Google Colab)

3-D block diagram with a draped field and a linked chart

Storm Ciarán crosses north-west Europe

A block of north-west Europe is cut out, its relief is exaggerated 40 times, and the wind 10 m above the ground is laid on it in colour. Places calmer than 8 m/s keep the bare grey relief, so the gale is the only colour. The chart at the top right gives the wind at Brest and at London for the same hours, with a playhead at the hour shown. The relief is not to scale and the far side of the block is foreshortened: use the chart for numbers.

Steps to make it

  1. Load the hourly 10-m wind (data/gis_styles/ciaran.npz) and the relief at 2 arc-minutes (terrain_nweurope.npz).
  2. Set an oblique parallel camera: it looks towards 24° from north, 35° above the horizon; relief ×40.
  3. Compute once, in numpy, which ground point each screen pixel sees (a lookup table pixel → latitude, longitude).
  4. Shade the relief from the north-west, add the walls of the slab and its shadow.
  5. Sample the wind speed of one hour through the lookup and lay it on the ground, transparent below 8 m/s.
  6. Add the chart of the grid cells nearest Brest and London, the clock, place names, north arrow and credits; save the poster (03 UTC, 2 November).
  7. For the video, repeat the sampling for 47 hours, four frames per hour, and encode with ffmpeg.

# %% [markdown]
# # 3 · 3-D block diagram with a draped field and a linked chart
#
# **The idea.** Cut a rectangular piece of the Earth out like a slice of cake, exaggerate its relief, look at it
# from above and to one side, and drape a data field on its surface. Animate the field, and let a small chart of
# the same field at one or two places carry the playhead. Relief gives the eye a sense of place that a flat map
# does not; the chart gives the numbers that the oblique view cannot.
#
# **This map.** Storm Ciarán's 10-m wind (ERA5, hourly) on the relief of north-west Europe (ETOPO 2022).
#
# No 3-D library is used: the block is drawn with numpy only, and that is what this tutorial explains.
#
# Steps: 1 data → 2 the camera → 3 "which ground does each pixel see" → 4 light and walls → 5 drape the
# field → 6 the finished frame → 7 the animation.

# %% [markdown]
# ## Settings
# Everything you may want to change is in this one cell. The checks at the bottom **stop** the notebook with a plain
# message if a setting cannot work, before anything slow starts.

print("terrain", z.shape, "| highest point", z.max(), "m | wind hours", len(wind["time"]))

# %% [markdown]
# ## 2 · The camera
# A parallel (orthographic) camera has two angles: the **azimuth** it looks towards (24° = towards north-
# north-east, so the south edge is nearest to us) and its **tilt** above the horizon (35°). A point that lies
# `v` km away from us along the ground and `h` metres high lands on the screen at
#
# `screen_y = y0 − v · sin(tilt) / (km per pixel) − h · (exaggeration) · cos(tilt) / (km per pixel)`
#
# Going further away moves a point up the screen; so does height. Relief is exaggerated 40 times here and the
# figure says so: at true scale the Alps (4 km) on a 2000-km block would be two pixels high.

# %% [markdown]
# ## 3 · Which ground does each pixel see?
# Turn the terrain so the camera looks straight "up the rows" (row 0 nearest). In one screen column, walk away
# from the camera: each row's surface reaches some screen height. A pixel shows the **nearest** row whose surface
# reaches at least that high. `Block` finds this for all pixels at once:
#
# 1. compute the screen height of every (row, column) cell;
# 2. write each row number into an image at that height, keeping the smallest row (`np.minimum.at`);
# 3. fill downwards with a running minimum (`np.minimum.accumulate`): whatever is below a surface's top and not
#    hidden by a nearer row belongs to that row.
#
# The result is a lookup table "screen pixel → (lat, lon)". It depends only on the terrain and the camera, so it
# is computed **once**; every animation frame is just a sampling of that hour's field through the table.

# %%
blk = block.Block(z, lat, lon, azimuth=AZIMUTH, tilt=TILT, km_per_px=1.72, zexag=40.0, W=1500, H=900)
fig, axs = plt.subplots(1, 3, figsize=(15, 3.4))
axs[0].imshow(np.where(blk.surf, blk.plat, np.nan)); axs[0].set_title("latitude seen by each pixel")
axs[1].imshow(np.where(blk.surf, blk.plon, np.nan)); axs[1].set_title("longitude seen by each pixel")
axs[2].imshow(np.where(blk.surf, blk.height, np.nan), cmap="gray"); axs[2].set_title("height seen (m)")
for a in axs:
    a.axis("off")
plt.tight_layout(); plt.show()

# %% [markdown]
# ## 4 · Light and walls
# The relief is lit from the north-west (the convention for relief maps: with light from the south many people
# see valleys as ridges). Shading is computed on the terrain grid from its slopes and read through the lookup.
# Pixels below the nearest row's surface, down to a fixed thickness, are the **walls** of the slab; a blurred,
# shifted copy of the block's silhouette is its shadow on the ground.

# %%
bare = np.where((blk.height > 0)[..., None], C.rgb("#5b647a"), C.rgb("#1d2b4a")).astype(np.float32)

# ## 5 · Drape the field
# The wind speed of one hour is sampled at each pixel's (lat, lon), coloured, and laid on the ground with an
# opacity that rises from 0 at 8 m/s to full at 12 m/s: calm regions keep the bare relief, and the gale is
# the only colour on the picture. The colour bar shows the same ramp and states the cut-off.

Where the water vapour sits

Height and colour both show the same thing: the water vapour in the whole column of air above each place, as the depth of water it would make if it all fell as rain (mm). The field is cut into bands of 5 mm and lit from the north-west, so each band is a terrace. In July the monsoon stands as a high plateau over the Ganges plain and the Bay of Bengal, and the dry Tibetan Plateau is a deep blue floor. The hills are data, not mountains.

# %% [markdown]
# ## 2 · The map grid and the land mask
# Lambert azimuthal equal-area, centred on India: equal areas matter because we will quote a mean over the
# land in view. The 1° field is resampled to the pixels with a cubic spline (`order=3`), which gives the smooth
# surface this style needs. The land mask comes from Natural Earth.

# %%
grid = C.MapGrid.fit("+proj=laea +lat_0=21.5 +lon_0=81", 0, 0, 4300e3, 1120, 1020)
land = grid.land("50m", soft=1.0)
july = grid.sample(data["tcwv"][6], data["lat"], data["lon"], order=3)
print("pixels:", grid.w, "x", grid.h, "| July range on land:", round(float(np.nanmin(july[land > 0.5])), 1), "to",
      round(float(np.nanmax(july[land > 0.5])), 1), "mm")

# %% [markdown]
# ## 3 · Bands
# Fifteen bands of 5 mm, from 0 to 75 mm (the wettest land pixel in July holds 71 mm). A banded map can be read against its colour bar (a smooth ramp cannot, once it is
# shaded), and the band edges will become the terraces. The colour map is `cmocean.haline`: dark blue for dry,
# through green, to pale yellow for moist; it only gets lighter, so it survives greyscale and colour-blind
# viewing.

# %%
levels = np.arange(0, 80, 5)
flat = C.colourise(july, cmocean.cm.haline, 0, 75, levels=levels)

# %% [markdown]
# ## 4 · Terraces and light
# `relief.terrace` mixes the smooth field with its band number, so each band edge is a small step; `C.hillshade`
# lights that surface from the north-west (azimuth 315°, 42° above the horizon). The colour is multiplied by
# `ambient + light × shade`, and a thin dark line marks every band edge.

# %%
height = relief.terrace(np.nan_to_num(july), levels)
shade = C.hillshade(height, 315, 42, zfactor=3.4)

# v2.1, public domain) and the daily sea-ice extent of both hemispheres (NSIDC Sea Ice Index v4), in one small file.

import matplotlib.pyplot as plt
import cmocean

data = nb.load("oisst_2025")                # 24 snapshots (1st and 16th of each month) on 0.5 degrees
print("snapshots:", len(data["date"]), "|", data["date"][0], "...", data["date"][-1])

# %% [markdown]
# ## 2 · The projection
# PROJ knows it as `+proj=spilhaus` (since version 9.6). The whole world fills a square about 23,500 km on a
# side in projected metres. Its two opposite corners are one point each on land: 30°N 115°E in China and 30°S 65°W in Argentina. `MapGrid`
# gives, for every pixel of that square, the longitude and latitude it shows.

# %%
grid = spilhaus.spilhaus_grid(1000)
plon, plat = grid.lonlat()
fig, axs = plt.subplots(1, 2, figsize=(10, 4.8))
axs[0].imshow(plat, cmap="RdBu_r"); axs[0].set_title("latitude of each pixel")
axs[1].imshow(plon, cmap="twilight"); axs[1].set_title("longitude of each pixel")
for a in axs:
    a.axis("off")
plt.tight_layout(); plt.show()

# %% [markdown]
# ## 3 · Sample the fields through the projection
# We never "re-project polygons" (they would tear at the cuts). We go the other way: each pixel asks the data
# grid for its value (`grid.sample`, bilinear, wrapping in longitude). The land mask is a plain lat/lon raster
# of Natural Earth sampled the same way, so it also survives the cuts.

# %%
k = 17                                                     # 16 September
sst = data["sst_c100"][k].astype(np.float32) / 100.0
sst[data["sst_c100"][k] == -9999] = np.nan
ice = data["ice_pct"][k] / 100.0
ice = np.where(np.nan_to_num(sst, nan=9) <= 1.5, ice, 0)   # drop stray "ice" in water too warm for it

Cut-away globe

Inside the Pacific

The globe shows the temperature of the sea surface. A wedge is cut out of the Pacific north of the Equator, and its three faces show the temperature below, down to 1000 m. Warm water turns out to be a thin skin on a cold ocean, and along the Equator that warm layer is deep in the west and shallow in the east. Depth is not to scale: 1000 m is drawn about 3,200 times too deep, and the figure says so.

Steps to make it

  1. Load the annual-mean temperature from the surface to 2000 m: data/gis_styles/woa23_temperature.npz.
  2. Cast one ray per pixel at a unit sphere with the wedge 180°-110°W, north of the Equator, removed.
  3. For each ray find what it hits: the surface, or one of the three flat faces of the wedge.
  4. Turn the hit point into latitude, longitude and depth (1000 m is drawn as half of the radius) and interpolate the temperature there.
  5. Colour it (cmocean thermal), add isotherms every 5 °C, depth arcs every 250 m, land and light.
  6. Add the labels, the colour bar, the note on the depth exaggeration and the credits; save the poster.
  7. For the video, turn the globe into place, open the wedge eastwards, then sway a few degrees; encode with ffmpeg.

# # 6 · Cut-away globe: a map and three sections in one object
#
# **The idea.** A globe shows a field on its surface. Cut a wedge out of it (a range of longitudes, north of the
# Equator) and paint what lies *below* the surface on the three flat faces of the cut: two meridians and the
# equatorial plane. The reader sees a map and three vertical sections that meet at the right places, with no need
# to work out where each section lies.
#
# **This map.** Annual-mean ocean temperature (World Ocean Atlas 2023) from the surface to 1000 m in the
# Pacific, cut along 180°, 110°W and the Equator.
#
# Steps: 1 data → 2 one ray per pixel → 3 through the wedge to a face → 4 from the hit point to a value →
# 5 colour, light and lines → 6 the finished frame → 7 the animation.

# ## 1 · The data
# Annual-mean ocean temperature from the surface to 2000 m on a 1° grid (World Ocean Atlas 2023, NOAA NCEI,

import numpy as np
import matplotlib.pyplot as plt
import cmocean

from gismaps.styles import common as C, cutaway      # the map-style code of this repository

data = nb.load("woa23_temperature")         # t_c100 (depth, lat, lon) in 0.01 degrees C; -9999 = no water
print("grid:", data["t_c100"].shape, "| depths:", data["depth_m"][0], "to", data["depth_m"][-1], "m")

# %% [markdown]
# ## 2 · One ray per pixel
# The camera is far away (parallel rays). For a pixel at (x, y), in Earth radii from the centre of the disc, the
# ray meets the unit sphere at the point `P = x·right + y·up + sqrt(1 − x² − y²)·forward`. Its longitude and
# latitude follow from P. If that point is outside the wedge, the pixel shows the **surface**.

# %% [markdown]
# ## 3 · Through the wedge to a face
# If the point is inside the wedge, there is no surface there: the ray flies on, in a straight line away from the
# camera, until it leaves the wedge. The wedge is bounded by three planes (meridian A, meridian B, the Equator), so
# the exit point is the nearest of three ray-plane intersections. That point has a radius between 0 and 1 and
# lies on one of the three **faces**.
#
# `cutaway.raycast` does this for every pixel at once and returns what each pixel is and where its point lies.

# %%
rc = cutaway.raycast(600, lon_c=212, lat_c=30, lon_a=LON_WEST, lon_b=LON_EAST)
fig, axs = plt.subplots(1, 3, figsize=(14, 4.6))
axs[0].imshow(rc["kind"], cmap="tab10", vmin=0, vmax=9); axs[0].set_title("what each pixel is: surface or one of three faces")
axs[1].imshow(rc["lat"], cmap="RdBu_r"); axs[1].set_title("latitude of the point seen")
axs[2].imshow(rc["rad"], cmap="viridis"); axs[2].set_title("radius of the point seen (1 = surface)")
for a in axs:
    a.axis("off")
plt.tight_layout(); plt.show()

# %% [markdown]
# ## 4 · From the hit point to a value
# A face pixel knows its longitude, latitude and radius. Radius is turned into depth with a **stated, linear**
# scale: radius 1 is the surface and radius 0.5 is 1000 m. That is about 3,200 times deeper than true scale
# (1000 m is 0.016 % of Earth's radius), so the figure says "not to scale" in words. The temperature is then
# read from the atlas at (depth, latitude, longitude) by linear interpolation; where there is no water (land, sea
# floor) the face is grey.

# %%
globe = cutaway.OceanCutaway(data, lon_a=LON_WEST, lon_b=LON_EAST)
exaggeration = (1 - globe.R_IN) * 6371e3 / globe.zmax
print(f"depth exaggeration: about {exaggeration:,.0f} times")
depths = np.array([0, 100, 200, 300, 500, 1000.0])
rad = 1 - depths / globe.zmax * (1 - globe.R_IN)
for name, lo in (("west face", LON_WEST), ("east face", LON_EAST)):
    t = globe.interior_t(np.zeros_like(rad), np.full_like(rad, lo), rad)
    print(f"Equator at {name:12s}:", "  ".join(f"{d:.0f} m {v:4.1f}" for d, v in zip(depths, t)), "(deg C)")

# %% [markdown]
# The numbers show what the equatorial face tells: at 180° the water is still about 28 °C at 100 m, while
# at 110°W it is about 15 °C at the same depth, some 13 degrees colder. The warm layer is deep in the west and
# shallow in the east.

# %% [markdown]
# ## 5 · Colour, light and lines
# Surface and faces share one colour bar (`cmocean.thermal`, −2 to 30 °C). The sphere is shaded as a ball;
# each face gets one brightness from its angle to the light, so the three faces can be told apart. Dark lines on
# the faces mark every 5 °C, white arcs every 250 m, and a light outline separates the parts.

# %%
img = globe.globe(700, lon_c=212, lat_c=30)
plt.figure(figsize=(7.5, 7.5), facecolor=C.BG); plt.imshow(img); plt.axis("off"); plt.show()

import matplotlib.pyplot as plt

from gismaps import prepare_data as P                 # how the reduced file is made (and the live STAC readers)
from gismaps.styles import common as C, satellite     # the map-style code of this repository

print("area (W, S, E, N):", P.S2_AOI)
print("years:", P.S2_YEARS[0], "to", P.S2_YEARS[-1], "| season: 15 January to 5 March | pixel:", P.S2_RES, "m")

# %% [markdown]
# ## 2 · Route (a): find the scenes with a STAC search
# A STAC catalogue is a searchable index of scenes. Element 84's Earth Search is public: no key, no account.
# We ask for Sentinel-2 L2A (surface reflectance) scenes over the box, in the dry season, with under 5 % cloud,
# on one MGRS tile (so every year lands on the same pixel grid), and take the clearest ones.
#
# This cell runs when `pystac-client` and `rasterio` are installed (they are in Colab after the setup cell) and the
# catalogue answers; otherwise it is skipped and the reduced file is used, so the notebook always runs to the end.

# %%
try:
    import pystac_client, rasterio              # noqa: F401, E401
    LIVE = True
except ImportError:
    LIVE = False
    print("pystac-client / rasterio not installed here: using the reduced file (the live cells are skipped)")

if LIVE:
    try:
        items = P.s2_pick(P.S2_YEARS[-1], n=4)
        for it in items:
            print(it.id, it.datetime.date(), f"cloud {it.properties['eo:cloud_cover']:.2f} %")
    except Exception as err:                     # noqa: BLE001  (the public catalogue is busy or unreachable)
        LIVE = False
        print("Earth Search did not answer (", str(err)[:80], "): using the reduced file")

# %% [markdown]
# ## 3 · Read only a window, then the water index
# A Sentinel-2 tile is 110 km across at 10 m: hundreds of megabytes per band. A cloud-optimised GeoTIFF lets
# `rasterio` read **only our window, at a coarser overview** (here 40 m) over HTTP: a few hundred kilobytes.
#
# Water is dark in the short-wave infrared and brighter in green, so the Modified Normalised Difference Water
# Index, `MNDWI = (green − SWIR) / (green + SWIR)`, is positive on water and negative on land.
#
# **A trap worth knowing.** Since January 2022 ESA adds 1000 to every L2A value. Some catalogue copies have
# removed it again, some have not, and the metadata flag was wrong for one of our eight years. `s2_window`
# therefore decides from the data (is anything darker than 1000?) and subtracts the offset if it is there. Without
# that, the 2022 index is squeezed towards zero and the river nearly vanishes.

# %%
index = data["mndwi100_latest"] / 100.0          # the stored median index of the newest year (used if the live read fails)
if LIVE:
    try:
        d = P.s2_window(items[0])                # green, swir16, scl (scene classification) for the window
        index = P.mndwi(d["green"], d["swir16"])
        print("window:", index.shape, "px | offset subtracted:", d["dn_offset"],
              "| clouds, shadows, no data flagged by SCL:", f"{100 * np.isin(d['scl'], (0, 1, 3, 8, 9, 10)).mean():.2f} %")
    except Exception as err:                     # noqa: BLE001
        print("the scene could not be read (", str(err)[:80], "): showing the stored index")

fig, axs = plt.subplots(1, 2, figsize=(9, 6.6))
axs[0].imshow(data["rgb_latest"]); axs[0].set_title(f"true colour, {data['rgb_date']}")

for a in axs:
    a.axis("off")
plt.colorbar(im, ax=axs[1], shrink=0.7); plt.tight_layout(); plt.show()

# %% [markdown]
# ## 4 · From index to "the river"
# Two decisions, both stated on the final figure:
# * **threshold** MNDWI > 0.1 (a little above 0 keeps wet sand and damp fields out);
# * **size**: keep only connected water of at least 5 km². In February the fields beside the river are
#   flooded for rice; they are water, but they are not the river.

def gee_periods(years=P.S2_YEARS, start="01-15", end="03-06"):
    """One (label, start, end) per dry season. For monthly work: one tuple per month instead."""
    return [(str(y), f"{y}-{start}", f"{y}-{end}") for y in years]


def gee_mndwi(region, start, end):
    """Median MNDWI x 100 (int8) of the clear Sentinel-2 scenes of one period, clouds masked with SCL."""
    col = (ee.ImageCollection("COPERNICUS/S2_SR_HARMONIZED").filterBounds(region).filterDate(start, end)
           .filter(ee.Filter.lt("CLOUDY_PIXEL_PERCENTAGE", 10)))
    clear = col.map(lambda im: im.updateMask(im.select("SCL").remap([0, 1, 3, 8, 9, 10], [0] * 6, 1)))
    return clear.median().normalizedDifference(["B3", "B11"]).multiply(100).round().toInt8().unmask(-128), col.size()

# ## 2 · From longitude and latitude to poster pixels
# A city is small, so the simplest honest map works: a **local equirectangular** map. One degree of latitude is
# about 110.574 km everywhere; one degree of longitude is 111.320 km × cos(latitude), because the meridians close in
# toward the poles.
#
# $$x = 985 + \frac{(\lambda-\lambda_0)\,111\,320\,\cos\varphi_0}{\text{mpp}},\qquad
#   y = 1420 - \frac{(\varphi-\varphi_0)\,110\,574}{\text{mpp}}$$
#
# ($\lambda$ = longitude, $\varphi$ = latitude, both in degrees; the minus sign is there because pixel rows count
# downward while latitude counts upward.) Over 10 km the error is below 0.1 %.

# %% RUN :: Longitude and latitude to pixels :: One point by hand, then the poster's function, then a check that they agree.
# --- from scratch: one point, one step per line ---
lon, lat = 153.0260, -27.4698  # a point in central Brisbane (degrees east, degrees north)
lat0, lon0, mpp = cfg["lat0"], cfg["lon0"], cfg["mpp"]  # the map's anchor point and scale
m_per_deg_lon = 111_320.0 * np.cos(np.radians(lat0))  # metres in one degree of longitude at this latitude
m_per_deg_lat = 110_574.0  # metres in one degree of latitude
east_m = (lon - lon0) * m_per_deg_lon  # how far east of the anchor, in metres
north_m = (lat - lat0) * m_per_deg_lat  # how far north of the anchor, in metres
x = 985 + east_m / mpp  # pixels to the right of the left edge
y = 1420 - north_m / mpp  # pixels down from the top edge (north is up, so subtract)
print(f"{east_m:.0f} m east, {north_m:.0f} m north of the anchor -> pixel ({x:.1f}, {y:.1f})")

# --- the function the poster uses, and a check that both agree ---
pr = city.Proj(cfg)
np.testing.assert_allclose((x, y), pr.xy(lon, lat), rtol=1e-12)  # same formula, so they agree to rounding error
print("Proj.xy agrees. 1 km on the ground =", round(1000 / mpp), "pixels.")

# %% RUN :: Load the city layers :: Uses LIVE_OSM from the settings cell: the shipped extract (fast) or your own download (about 35 minutes).
def load_city(cfg: dict, live: bool = False) -> dict:
    """The layers of one city in poster pixels: water, land use, roads, rails, buildings, amenity points."""
    pr = city.Proj(cfg)
    if live:
        try:
            folder = Path("lens_cache") / f"OSM-overpass-{cfg['key']}"
            osm.fetch_city(cfg, folder, pause=8.0)  # polite, cached, tiled, retried; resumes if interrupted
            return city.read_raw(cfg, pr, folder)  # raw Overpass answers -> shapely polygons in pixels
        except Exception as e:  # noqa: BLE001
            print("Overpass did not finish (", str(e)[:80], ") - using the pre-extracted file instead.")
    return city.read_derived(cfg, pr, data_file(f"{cfg['key']}_lens_layers.json.gz"))

# %% [markdown]
# ## 4 · From OSM elements to shapely polygons
# Overpass returns *elements*. Two kinds matter here:
#
# * a **way**: a list of points. If the first and last point are the same, it is an area (a building, a park);
# * a **relation** of type *multipolygon*: several ways with a role, `outer` or `inner`. A park with a lake in it is
#   an outer ring with an inner ring (a hole). The outer ways may be several pieces that only join end to end.
#
# `city.polys` turns either into [shapely](https://shapely.readthedocs.io) polygons: a closed way directly;
# a relation by **polygonizing** the outer pieces and **subtracting** the polygonized inner pieces.
# A hand-made example, in the exact shape Overpass uses:

# %% RUN :: OSM elements to shapely polygons :: A hand-made way and a multipolygon relation with a hole.
def pt(lon, lat):  # one Overpass point
    return {"lon": lon, "lat": lat}


square = [pt(153.020, -27.470), pt(153.022, -27.470), pt(153.022, -27.472), pt(153.020, -27.472), pt(153.020, -27.470)]
hole = [pt(153.0207, -27.4707), pt(153.0213, -27.4707), pt(153.0213, -27.4713), pt(153.0207, -27.4713), pt(153.0207, -27.4707)]
way = {"type": "way", "id": 1, "tags": {"building": "yes"}, "geometry": square}  # a closed way = one polygon
relation = {"type": "relation", "id": 2, "tags": {"leisure": "park", "type": "multipolygon"},  # a park ...
            "members": [{"type": "way", "role": "outer", "geometry": square[:3]},  # ... whose outer ring comes in two pieces
                        {"type": "way", "role": "outer", "geometry": square[2:]},
                        {"type": "way", "role": "inner", "geometry": hole}]}  # ... with a hole (a pond, say)
a = city.polys(way, pr)[0]  # shapely Polygon in poster pixels
b = city.polys(relation, pr)[0]
m2 = cfg["mpp"] ** 2  # one pixel covers mpp x mpp square metres
print(f"way      -> {a.geom_type}, {a.area * m2:,.0f} m²")
print(f"relation -> {b.geom_type}, {b.area * m2:,.0f} m², holes: {len(b.interiors)}")
assert b.area < a.area and len(b.interiors) == 1  # the hole was cut out

# %% [markdown]
# ## 6 · A lens is a mask
# A lens is a disc. Inside the disc we show the lens picture, outside it the base map. With a mask $a$ that is 1
# inside and 0 outside (and in between on the one-pixel edge, so the edge is smooth):
#
# $$\text{out} = \text{base}\,(1-a) + \text{lens}\cdot a$$
#
# **Where two lenses overlap** there is a choice, one number called `overlap`:
#
# * `overlap = 0.5` - the upper lens is mixed half and half with the lower one. This is the poster look. It is fine
#   here because these are *categorical* pictures: nobody reads a number off a blended colour.
# * `overlap = 0` - the lower lens keeps its exact colours. Use this for any **data field with a colour bar**
#   (tutorial 2): a 50/50 mix of two colour maps matches neither colour bar.
#
# From scratch first, then the library function, then a check that they agree.

# %% RUN :: A lens is a mask :: The blend formula from scratch, the library call, and a check that they agree.
# --- from scratch ---
h, w = layers["base"].shape[:2]  # 2828 rows, 2000 columns
discs = city.lens_discs(cfg)  # [(centre x, centre y, radius)] for land use, public realm, morphology
yy, xx = np.mgrid[0:h, 0:w].astype(np.float32)  # the row and column number of every pixel


def disc_mask(cx, cy, r):
    d = np.hypot(xx + 0.5 - cx, yy + 0.5 - cy)  # distance of each pixel centre from the lens centre
    return np.clip(r - d + 0.5, 0, 1)  # 1 inside, 0 outside, a smooth ramp across the one-pixel edge


masks = [disc_mask(*d) for d in discs]
out = layers["base"].copy()  # start from the base map
overlap = 0.5  # the poster look for categorical maps
for j, key in enumerate(("use", "pub", "mor")):  # lenses in drawing order
    a = masks[j].copy()  # this lens's own disc
    for i in range(j):  # wherever an earlier lens already lies ...
        a *= 1 - (1 - overlap) * masks[i]  # ... draw this one at `overlap` strength only
    out = out * (1 - a[..., None]) + layers[key] * a[..., None]  # the blend formula, for all three colour channels

# --- the function the poster uses ---
lenses = city.make_lenses(cfg, layers)  # three lc.Lens objects (picture, centre, radius, rim colour, overlap 0.5)
img = lc.composite(layers["base"], lenses)
np.testing.assert_allclose(out, img, atol=1e-6)  # same arithmetic in float32, so equal to rounding error
print("scratch composite == lc.composite. Lens order:", [d[:2] for d in discs])
show((img[crop][::2, ::2] * 255).astype(np.uint8), 900)

# %% [markdown]
# ## 8 · Why it looks the way it does
#
# | Choice | Reason |
# |---|---|
# | Black sheet, base map almost black | the lenses are the subject; the base only says "the city goes on" (the river shape orients the reader) |
# | Land use: light, flat, well-separated hues | a categorical map: classes must be told apart, not ranked. Residential (the most ground) gets the quietest colour |
# | "No land-use polygon in OSM" has its own dark swatch | honest emptiness: unmapped ground is shown as unmapped, not as some class |
# | Public realm: dark brown ground, green parks, small bright symbols | points must pop; each amenity gets its own shape *and* colour, so the map does not rely on colour alone |
# | Morphology: light buildings on dark green-grey, thin white streets | a figure-ground drawing: form only, no categories |
# | Rim colours pink / amber / green, repeated on the label bars | the rim colour is the link between a lens and its label, so no label has to sit inside a lens |
# | Lens order: land use, public realm, morphology | the overlaps mix neighbours; the most detailed drawing (buildings) goes on top, where it survives a 50 % mix |
# | `overlap = 0.5` | the poster look; allowed because no colour here is a measured value |
# | Scale bar and north arrow | a 10-km city map is true to scale and north-up everywhere, so both are honest here |
# | Credit block | the map's author, the data licence (© OpenStreetMap contributors, ODbL) and the style credit are always printed |

# %% [markdown]
# ## 2 · From longitude and latitude to poster pixels
# A city is small, so the simplest honest map works: a **local equirectangular** map. One degree of latitude is
# about 110.574 km everywhere; one degree of longitude is 111.320 km × cos(latitude), because the meridians close in
# toward the poles.
#
# $$x = 985 + \frac{(\lambda-\lambda_0)\,111\,320\,\cos\varphi_0}{\text{mpp}},\qquad
#   y = 1420 - \frac{(\varphi-\varphi_0)\,110\,574}{\text{mpp}}$$
#
# ($\lambda$ = longitude, $\varphi$ = latitude, both in degrees; the minus sign is there because pixel rows count
# downward while latitude counts upward.) Over 10 km the error is below 0.1 %.

# %% RUN :: Longitude and latitude to pixels :: One point by hand, then the poster's function, then a check that they agree.
# --- from scratch: one point, one step per line ---
lon, lat = 153.0260, -27.4698  # a point in central Brisbane (degrees east, degrees north)
lat0, lon0, mpp = cfg["lat0"], cfg["lon0"], cfg["mpp"]  # the map's anchor point and scale
m_per_deg_lon = 111_320.0 * np.cos(np.radians(lat0))  # metres in one degree of longitude at this latitude
m_per_deg_lat = 110_574.0  # metres in one degree of latitude
east_m = (lon - lon0) * m_per_deg_lon  # how far east of the anchor, in metres
north_m = (lat - lat0) * m_per_deg_lat  # how far north of the anchor, in metres
x = 985 + east_m / mpp  # pixels to the right of the left edge
y = 1420 - north_m / mpp  # pixels down from the top edge (north is up, so subtract)
print(f"{east_m:.0f} m east, {north_m:.0f} m north of the anchor -> pixel ({x:.1f}, {y:.1f})")

# --- the function the poster uses, and a check that both agree ---
pr = city.Proj(cfg)
np.testing.assert_allclose((x, y), pr.xy(lon, lat), rtol=1e-12)  # same formula, so they agree to rounding error
print("Proj.xy agrees. 1 km on the ground =", round(1000 / mpp), "pixels.")

# %% [markdown]
# ## 3 · Asking OpenStreetMap, politely
# The [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API) answers questions such as *"every way tagged
# `building` inside this box"*. It is a free, shared server, so we follow four rules (all built into
# `gismaps.lens.osm.fetch_city`):
#
# 1. **One query at a time**, with a pause (8 s) between queries, and a `User-Agent` that says what we are.
# 2. **Cache everything.** Every answer is saved as a file; a file on disk is never asked for again.
# 3. **Tile the heavy layer.** All buildings of a 7-km box in one query times out; 3 × 3 tiles do not (Dhaka needs 4 × 4).
#    A building on a tile edge comes back twice and is dropped by its OSM id.
# 4. **Expect "busy".** The server answers HTTP 429 / 502 / 504 when loaded; wait (30 s, 60 s ...) and try again.
#
# Here are the questions for Brisbane, in Overpass QL:

# %% RUN :: The Overpass questions :: Prints the queries; nothing is downloaded yet.

# %% [markdown]
# **Getting the whole city.** Two ways, same result:
#
# * `LIVE_OSM = False` (the default in the settings cell): load the **pre-extracted file** that ships with this tutorial. It is the reduced
#   result of exactly the queries above (coordinates kept to 6 decimals, clipped to the ground the lenses can reach).
# * `LIVE_OSM = True`: run all 14 queries yourself with `osm.fetch_city` (about 55 MB and 35 minutes for Brisbane on
#   the public server; the answers are cached in `lens_cache/`, so a second run is instant). If the server stays
#   busy, the cell falls back to the pre-extracted file and tells you.

# %% RUN :: Load the city layers :: Uses LIVE_OSM from the settings cell: the shipped extract (fast) or your own download (about 35 minutes).
def load_city(cfg: dict, live: bool = False) -> dict:
    """The layers of one city in poster pixels: water, land use, roads, rails, buildings, amenity points."""
    pr = city.Proj(cfg)
    if live:
        try:
            folder = Path("lens_cache") / f"OSM-overpass-{cfg['key']}"
            osm.fetch_city(cfg, folder, pause=8.0)  # polite, cached, tiled, retried; resumes if interrupted
            return city.read_raw(cfg, pr, folder)  # raw Overpass answers -> shapely polygons in pixels
        except Exception as e:  # noqa: BLE001
            print("Overpass did not finish (", str(e)[:80], ") - using the pre-extracted file instead.")
    return city.read_derived(cfg, pr, data_file(f"{cfg['key']}_lens_layers.json.gz"))

# %% [markdown]
# ## 4 · From OSM elements to shapely polygons
# Overpass returns *elements*. Two kinds matter here:
#
# * a **way**: a list of points. If the first and last point are the same, it is an area (a building, a park);
# * a **relation** of type *multipolygon*: several ways with a role, `outer` or `inner`. A park with a lake in it is
#   an outer ring with an inner ring (a hole). The outer ways may be several pieces that only join end to end.
#
# `city.polys` turns either into [shapely](https://shapely.readthedocs.io) polygons: a closed way directly;
# a relation by **polygonizing** the outer pieces and **subtracting** the polygonized inner pieces.
# A hand-made example, in the exact shape Overpass uses:

# %% RUN :: OSM elements to shapely polygons :: A hand-made way and a multipolygon relation with a hole.
def pt(lon, lat):  # one Overpass point
    return {"lon": lon, "lat": lat}


square = [pt(153.020, -27.470), pt(153.022, -27.470), pt(153.022, -27.472), pt(153.020, -27.472), pt(153.020, -27.470)]
hole = [pt(153.0207, -27.4707), pt(153.0213, -27.4707), pt(153.0213, -27.4713), pt(153.0207, -27.4713), pt(153.0207, -27.4707)]
way = {"type": "way", "id": 1, "tags": {"building": "yes"}, "geometry": square}  # a closed way = one polygon
relation = {"type": "relation", "id": 2, "tags": {"leisure": "park", "type": "multipolygon"},  # a park ...
            "members": [{"type": "way", "role": "outer", "geometry": square[:3]},  # ... whose outer ring comes in two pieces
                        {"type": "way", "role": "outer", "geometry": square[2:]},
                        {"type": "way", "role": "inner", "geometry": hole}]}  # ... with a hole (a pond, say)
a = city.polys(way, pr)[0]  # shapely Polygon in poster pixels
b = city.polys(relation, pr)[0]
m2 = cfg["mpp"] ** 2  # one pixel covers mpp x mpp square metres
print(f"way      -> {a.geom_type}, {a.area * m2:,.0f} m²")
print(f"relation -> {b.geom_type}, {b.area * m2:,.0f} m², holes: {len(b.interiors)}")
assert b.area < a.area and len(b.interiors) == 1  # the hole was cut out

# %% [markdown]
# ## 6 · A lens is a mask
# A lens is a disc. Inside the disc we show the lens picture, outside it the base map. With a mask $a$ that is 1
# inside and 0 outside (and in between on the one-pixel edge, so the edge is smooth):
#
# $$\text{out} = \text{base}\,(1-a) + \text{lens}\cdot a$$
#
# **Where two lenses overlap** there is a choice, one number called `overlap`:
#
# * `overlap = 0.5` - the upper lens is mixed half and half with the lower one. This is the poster look. It is fine
#   here because these are *categorical* pictures: nobody reads a number off a blended colour.
# * `overlap = 0` - the lower lens keeps its exact colours. Use this for any **data field with a colour bar**
#   (tutorial 2): a 50/50 mix of two colour maps matches neither colour bar.
#
# From scratch first, then the library function, then a check that they agree.

# %% RUN :: A lens is a mask :: The blend formula from scratch, the library call, and a check that they agree.
# --- from scratch ---
h, w = layers["base"].shape[:2]  # 2828 rows, 2000 columns
discs = city.lens_discs(cfg)  # [(centre x, centre y, radius)] for land use, public realm, morphology
yy, xx = np.mgrid[0:h, 0:w].astype(np.float32)  # the row and column number of every pixel


def disc_mask(cx, cy, r):
    d = np.hypot(xx + 0.5 - cx, yy + 0.5 - cy)  # distance of each pixel centre from the lens centre
    return np.clip(r - d + 0.5, 0, 1)  # 1 inside, 0 outside, a smooth ramp across the one-pixel edge


masks = [disc_mask(*d) for d in discs]
out = layers["base"].copy()  # start from the base map
overlap = 0.5  # the poster look for categorical maps
for j, key in enumerate(("use", "pub", "mor")):  # lenses in drawing order
    a = masks[j].copy()  # this lens's own disc
    for i in range(j):  # wherever an earlier lens already lies ...
        a *= 1 - (1 - overlap) * masks[i]  # ... draw this one at `overlap` strength only
    out = out * (1 - a[..., None]) + layers[key] * a[..., None]  # the blend formula, for all three colour channels

# --- the function the poster uses ---
lenses = city.make_lenses(cfg, layers)  # three lc.Lens objects (picture, centre, radius, rim colour, overlap 0.5)
img = lc.composite(layers["base"], lenses)
np.testing.assert_allclose(out, img, atol=1e-6)  # same arithmetic in float32, so equal to rounding error
print("scratch composite == lc.composite. Lens order:", [d[:2] for d in discs])
show((img[crop][::2, ::2] * 255).astype(np.uint8), 900)

# %% [markdown]
# ## 8 · Why it looks the way it does
#
# | Choice | Reason |
# |---|---|
# | Black sheet, base map almost black | the lenses are the subject; the base only says "the city goes on" (the river shape orients the reader) |
# | Land use: light, flat, well-separated hues | a categorical map: classes must be told apart, not ranked. Residential (the most ground) gets the quietest colour |
# | "No land-use polygon in OSM" has its own dark swatch | honest emptiness: unmapped ground is shown as unmapped, not as some class |
# | Public realm: dark brown ground, green parks, small bright symbols | points must pop; each amenity gets its own shape *and* colour, so the map does not rely on colour alone |
# | Morphology: light buildings on dark green-grey, thin white streets | a figure-ground drawing: form only, no categories |
# | Rim colours pink / amber / green, repeated on the label bars | the rim colour is the link between a lens and its label, so no label has to sit inside a lens |
# | Lens order: land use, public realm, morphology | the overlaps mix neighbours; the most detailed drawing (buildings) goes on top, where it survives a 50 % mix |
# | `overlap = 0.5` | the poster look; allowed because no colour here is a measured value |
# | Scale bar and north arrow | a 10-km city map is true to scale and north-up everywhere, so both are honest here |
# | Credit block | the map's author, the data licence (© OpenStreetMap contributors, ODbL) and the style credit are always printed |

# %% [markdown]
# ## 10 · What the map does not know
# A lens map of OSM is a map of *what volunteers have mapped*. Two numbers per city make that concrete: the share of
# the land-use lens with **no land-use polygon**, and the benches per km² in the public-realm lens. They differ a
# great deal, and that difference is about the map, not (only) about the cities.

# %% RUN :: What the map does not know :: Share of unmapped ground and amenities per km² in each city.
ground = lc.hexrgb("#2b2130")  # the colour of "no land-use polygon in OSM"
for key in ("brisbane", "dhaka", "richmond"):
    c = city_cfg(key)
    Lc = load_city(c)
    use = city.render_layers(c, Lc)["use"]  # the land-use picture
    cx, cy, r = city.lens_discs(c)[0]  # the land-use lens
    yy, xx = np.mgrid[0:use.shape[0], 0:use.shape[1]]
    inside = np.hypot(xx + 0.5 - cx, yy + 0.5 - cy) <= r  # pixels inside that lens
    empty = np.abs(use - ground).sum(-1) < 0.02  # pixels that still show the bare ground colour
    area_km2 = np.pi * (r * c["mpp"] / 1000) ** 2  # area of one lens
    n = city.count(c, Lc)["points_in_public_lens"]
    print(f"{c['name']:9s} no land-use polygon: {100 * (empty & inside).sum() / inside.sum():4.1f} % of the lens | "
          f"benches: {n.get('bench', 0) / area_km2:5.1f} per km² | toilets: {n.get('toilets', 0) / area_km2:4.1f} per km²")

# ## 2 · From longitude and latitude to poster pixels
# A city is small, so the simplest honest map works: a **local equirectangular** map. One degree of latitude is
# about 110.574 km everywhere; one degree of longitude is 111.320 km × cos(latitude), because the meridians close in
# toward the poles.
#
# $$x = 985 + \frac{(\lambda-\lambda_0)\,111\,320\,\cos\varphi_0}{\text{mpp}},\qquad
#   y = 1420 - \frac{(\varphi-\varphi_0)\,110\,574}{\text{mpp}}$$
#
# ($\lambda$ = longitude, $\varphi$ = latitude, both in degrees; the minus sign is there because pixel rows count
# downward while latitude counts upward.) Over 10 km the error is below 0.1 %.

# %% RUN :: Longitude and latitude to pixels :: One point by hand, then the poster's function, then a check that they agree.
# --- from scratch: one point, one step per line ---
lon, lat = 153.0260, -27.4698  # a point in central Brisbane (degrees east, degrees north)
lat0, lon0, mpp = cfg["lat0"], cfg["lon0"], cfg["mpp"]  # the map's anchor point and scale
m_per_deg_lon = 111_320.0 * np.cos(np.radians(lat0))  # metres in one degree of longitude at this latitude
m_per_deg_lat = 110_574.0  # metres in one degree of latitude
east_m = (lon - lon0) * m_per_deg_lon  # how far east of the anchor, in metres
north_m = (lat - lat0) * m_per_deg_lat  # how far north of the anchor, in metres
x = 985 + east_m / mpp  # pixels to the right of the left edge
y = 1420 - north_m / mpp  # pixels down from the top edge (north is up, so subtract)
print(f"{east_m:.0f} m east, {north_m:.0f} m north of the anchor -> pixel ({x:.1f}, {y:.1f})")

# --- the function the poster uses, and a check that both agree ---
pr = city.Proj(cfg)
np.testing.assert_allclose((x, y), pr.xy(lon, lat), rtol=1e-12)  # same formula, so they agree to rounding error
print("Proj.xy agrees. 1 km on the ground =", round(1000 / mpp), "pixels.")

# ## 4 · From OSM elements to shapely polygons
# Overpass returns *elements*. Two kinds matter here:
#
# * a **way**: a list of points. If the first and last point are the same, it is an area (a building, a park);
# * a **relation** of type *multipolygon*: several ways with a role, `outer` or `inner`. A park with a lake in it is
#   an outer ring with an inner ring (a hole). The outer ways may be several pieces that only join end to end.
#
# `city.polys` turns either into [shapely](https://shapely.readthedocs.io) polygons: a closed way directly;
# a relation by **polygonizing** the outer pieces and **subtracting** the polygonized inner pieces.
# A hand-made example, in the exact shape Overpass uses:

# %% RUN :: OSM elements to shapely polygons :: A hand-made way and a multipolygon relation with a hole.
def pt(lon, lat):  # one Overpass point
    return {"lon": lon, "lat": lat}


square = [pt(153.020, -27.470), pt(153.022, -27.470), pt(153.022, -27.472), pt(153.020, -27.472), pt(153.020, -27.470)]
hole = [pt(153.0207, -27.4707), pt(153.0213, -27.4707), pt(153.0213, -27.4713), pt(153.0207, -27.4713), pt(153.0207, -27.4707)]

            "members": [{"type": "way", "role": "outer", "geometry": square[:3]},  # ... whose outer ring comes in two pieces

                        {"type": "way", "role": "inner", "geometry": hole}]}  # ... with a hole (a pond, say)

# %% [markdown]
# ## 6 · A lens is a mask
# A lens is a disc. Inside the disc we show the lens picture, outside it the base map. With a mask $a$ that is 1
# inside and 0 outside (and in between on the one-pixel edge, so the edge is smooth):
#
# $$\text{out} = \text{base}\,(1-a) + \text{lens}\cdot a$$
#
# **Where two lenses overlap** there is a choice, one number called `overlap`:
#
# * `overlap = 0.5` - the upper lens is mixed half and half with the lower one. This is the poster look. It is fine
#   here because these are *categorical* pictures: nobody reads a number off a blended colour.
# * `overlap = 0` - the lower lens keeps its exact colours. Use this for any **data field with a colour bar**
#   (tutorial 2): a 50/50 mix of two colour maps matches neither colour bar.
#
# From scratch first, then the library function, then a check that they agree.

# %% RUN :: A lens is a mask :: The blend formula from scratch, the library call, and a check that they agree.
# --- from scratch ---
h, w = layers["base"].shape[:2]  # 2828 rows, 2000 columns
discs = city.lens_discs(cfg)  # [(centre x, centre y, radius)] for land use, public realm, morphology
yy, xx = np.mgrid[0:h, 0:w].astype(np.float32)  # the row and column number of every pixel


def disc_mask(cx, cy, r):
    d = np.hypot(xx + 0.5 - cx, yy + 0.5 - cy)  # distance of each pixel centre from the lens centre
    return np.clip(r - d + 0.5, 0, 1)  # 1 inside, 0 outside, a smooth ramp across the one-pixel edge


masks = [disc_mask(*d) for d in discs]
out = layers["base"].copy()  # start from the base map
overlap = 0.5  # the poster look for categorical maps
for j, key in enumerate(("use", "pub", "mor")):  # lenses in drawing order
    a = masks[j].copy()  # this lens's own disc
    for i in range(j):  # wherever an earlier lens already lies ...
        a *= 1 - (1 - overlap) * masks[i]  # ... draw this one at `overlap` strength only
    out = out * (1 - a[..., None]) + layers[key] * a[..., None]  # the blend formula, for all three colour channels

# --- the function the poster uses ---
lenses = city.make_lenses(cfg, layers)  # three lc.Lens objects (picture, centre, radius, rim colour, overlap 0.5)
img = lc.composite(layers["base"], lenses)
np.testing.assert_allclose(out, img, atol=1e-6)  # same arithmetic in float32, so equal to rounding error
print("scratch composite == lc.composite. Lens order:", [d[:2] for d in discs])
show((img[crop][::2, ::2] * 255).astype(np.uint8), 900)

# %% [markdown]
# ## 8 · Why it looks the way it does
#
# | Choice | Reason |
# |---|---|
# | Black sheet, base map almost black | the lenses are the subject; the base only says "the city goes on" (the river shape orients the reader) |
# | Land use: light, flat, well-separated hues | a categorical map: classes must be told apart, not ranked. Residential (the most ground) gets the quietest colour |
# | "No land-use polygon in OSM" has its own dark swatch | honest emptiness: unmapped ground is shown as unmapped, not as some class |
# | Public realm: dark brown ground, green parks, small bright symbols | points must pop; each amenity gets its own shape *and* colour, so the map does not rely on colour alone |
# | Morphology: light buildings on dark green-grey, thin white streets | a figure-ground drawing: form only, no categories |
# | Rim colours pink / amber / green, repeated on the label bars | the rim colour is the link between a lens and its label, so no label has to sit inside a lens |
# | Lens order: land use, public realm, morphology | the overlaps mix neighbours; the most detailed drawing (buildings) goes on top, where it survives a 50 % mix |
# | `overlap = 0.5` | the poster look; allowed because no colour here is a measured value |
# | Scale bar and north arrow | a 10-km city map is true to scale and north-up everywhere, so both are honest here |

Lens map · weather poster from ERA5

One storm, many realities · Storm Ciarán

Three fields of one storm at one hour (00 UTC, 2 November 2023): temperature about 1.5 km up, the moisture there, and sea-level pressure with the wind near the ground. Each lens keeps its exact colours where lenses overlap, and the upper lens adds only its lines, so every colour still matches its colour bar. Where all three meet you see a complete weather chart: the low (L, 955 hPa) with warm, moist air wrapping into it. In the video one clock steps all three fields hour by hour while the low crosses the lenses.

Steps to make it

  1. Get the ERA5 fields: the reduced 0.5° copy shipped with the repository (default), or the full 0.25° fields from the anonymous ARCO-ERA5 store (SOURCE = "arco", about 230 MB of transfer).
  2. Find the storm: follow the low from a seed point hour by hour and centre the map on it.

  4. Colour temperature (diverging, white at 0 °C) and humidity (sequential), each with its colour bar.
  5. Draw the line work: isobars every 4 hPa, moisture contours, wind arrows turned to the map's north.
  6. Cut the lenses with overlap = 0 (the no-blend rule): the lower lens keeps its colours, the upper adds only its lines.
  7. Add the title, the label blocks with their colour bars, the scale bar and credits; save the 2000 × 2828 px poster.
  8. Make the video (the layers of each hour are drawn once, one clock steps all three fields, frames are piped to ffmpeg) and convert it to the GIF.

# %% [markdown]
# # Lens map 2 · One storm, many realities
#
# **What you will make:** a poster of **Storm Ciarán** at 00 UTC on 2 November 2023, as it approached the English
# Channel. Three lenses look at the *same hour* of the *same storm*:
#
# | Lens | Field | Drawn as |
# |---|---|---|
# | **TEMPERATURE** | air temperature about 1.5 km up (the 850-hPa pressure level), °C | colour fill, blue-white-red, white at 0 °C |
# | **MOISTURE** | specific humidity at 850 hPa: grams of water vapour per kilogram of air | colour fill + dashed lines at 4, 6, 8 g/kg |
# | **PRESSURE & WIND** | sea-level pressure and the wind 10 m above the surface | isobars every 4 hPa + arrows |
#
# A few words first. **hPa** (hectopascal) is the unit of air pressure on weather maps; average sea-level pressure is
# about 1013 hPa. An **isobar** is a line of equal pressure. A **low** is a pressure minimum, the centre of a storm;
# in the Northern Hemisphere the wind blows anticlockwise around it (seen from above). **850 hPa** is the height
# where the pressure is 850 hPa, roughly 1.5 km up: high enough to be free of the ground's daily heating, so it shows
# the warm and cold air masses cleanly. **UTC** is the world's reference clock (Greenwich time, no summer time).
#
# **The new idea in this tutorial is the no-blend rule.** City maps could mix overlapping lenses half and half.
# Data fields must not: a mixed colour matches no colour bar. Here the overlaps become true *overlays* instead.
#
# **Data:** ERA5 reanalysis (Copernicus Climate Change Service / ECMWF) from the public ARCO-ERA5 store on Google
# Cloud, ETOPO 2022 relief (NOAA NCEI), Natural Earth coastlines. No key, no account.
# **Style** after Fan Mo, #30DayMapChallenge 2026 Day 14; the code and data here are original.
#
# **Time:** about 2 minutes, plus about 3 minutes of download when the ERA5 fields come straight from the cloud.

# ## 1 · The data: ERA5 from a public cloud store
# **ERA5** is a *reanalysis*: a weather model run over the past, corrected every hour with the observations of that

#

# %% [markdown]
# ## 2 · Finding the storm: a seeded low tracker
# The poster is centred on the low. Finding it sounds easy ("the lowest pressure on the map") and is a classic trap:
# a large map usually holds *several* lows, and the deepest one is not always the one you mean.
#
# The fix is to **follow one low**: start in a small box where and when you know the storm is (the *seed*: the
# western English Channel at 06 UTC on 2 November), then step hour by hour, each time taking the minimum only within
# 2.5° of the last position.

# %% RUN :: Track the low :: One tracking step from scratch, then the whole track against the whole-map minimum.
msl = sfc.mean_sea_level_pressure  # pascals; dimensions (time, latitude, longitude)
ts = sfc.time.values
seed_i = int(np.where(ts == np.datetime64(lw.SEED_TIME))[0][0])  # index of the seed hour
track = lw.track_low(msl, seed_i)  # [(lon, lat, hPa)] for every hour of `sfc`
i = int(np.where(ts == np.datetime64(HOUR))[0][0])  # index of the poster hour
lon0, lat0, p0 = track[i]

# --- from scratch: one tracking step, from the hour after the poster hour back to the poster hour ---
lon_next, lat_next, _ = track[i + 1]  # where the low is one hour later (already known)
near = msl.isel(time=i).sel(longitude=slice(lon_next - 3.75, lon_next + 3.75),  # 2.5° x 1.5 east-west (degrees of longitude are shorter)
                            latitude=slice(lat_next - 2.5, lat_next + 2.5))  # 2.5° north-south
k = np.unravel_index(int(near.values.argmin()), near.shape)  # row and column of the smallest value in that window
scratch = (float(near.longitude[k[1]]), float(near.latitude[k[0]]), float(near.values[k]) / 100.0)  # Pa -> hPa
assert scratch == (lon0, lat0, p0)  # the same grid point: this is exactly what track_low does at each step

# --- the trap: the minimum of the whole map, hour by hour ---
print("hour (UTC)     tracked low                whole-map minimum")
for j in range(0, len(ts), max(1, len(ts) // 8)):
    a = msl.isel(time=j)
    kk = np.unravel_index(int(a.values.argmin()), a.shape)
    naive = (float(a.longitude[kk[1]]), float(a.latitude[kk[0]]), float(a.values[kk]) / 100.0)
    flag = "" if abs(naive[0] - track[j][0]) < 3 and abs(naive[1] - track[j][1]) < 3 else "   <- a different low"
    print(f"{str(ts[j])[5:13]}   {track[j][0]:7.2f}°E {track[j][1]:5.2f}°N {track[j][2]:6.1f} hPa   "
          f"{naive[0]:7.2f}°E {naive[1]:5.2f}°N {naive[2]:6.1f} hPa{flag}")
print(f"\nPoster hour: the low is at {abs(lon0):.2f}°{'W' if lon0 < 0 else 'E'}, {lat0:.2f}°N, {p0:.0f} hPa.")

# %% [markdown]
# ## 3 · The map: a Lambert conformal pixel grid
# This map is 2,900 km wide. At that size the choice of projection matters. We use the **Lambert conformal conic**
# projection, the usual one for mid-latitude weather maps: it is *conformal* (angles and shapes are kept: a circular
# storm stays circular) and distances are true along two chosen "standard" parallels (45°N and 58°N here) and close
# to true between them.
#
# `lw.Grid` ties the projection to output pixels: pixel → metres on the projection plane → longitude and latitude.
# Every layer is then computed **at the pixel centres of this one grid**; matplotlib never chooses an extent.
#
# One consequence of a conic map: **north is not "up" everywhere.** The meridians fan out, so north tilts to the
# left on the left side of the sheet and to the right on the right side. That is why this poster has a faint
# graticule and a note instead of a north arrow.

# %% RUN :: The Lambert pixel grid :: Longitude and latitude to pixels, and how far north turns across the sheet.
g = lw.poster_grid(lon0, lat0)  # 2000 x 2828 px, 1.45 km per pixel, the low a little below and right of the middle
cx, cy = (float(v) for v in g.ll2px(lon0, lat0))  # where the low falls on the sheet
print(f"{g.mpp / 1000:.2f} km per pixel -> the sheet shows {g.w * g.mpp / 1e6:.2f} x {g.h * g.mpp / 1e6:.2f} thousand km; the low is at pixel ({cx:.0f}, {cy:.0f})")

# --- from scratch: longitude/latitude -> pixel, one step per line ---
x_m, y_m = g.proj(lon0 + 10.0, lat0)  # a point 10° east of the low, in metres on the projection plane (pyproj)
px = g.cx + x_m / g.mpp  # metres -> pixels, counted from the pixel of the projection centre
py = g.cy - y_m / g.mpp  # pixel rows count downward, so subtract
np.testing.assert_allclose((px, py), g.ll2px(lon0 + 10.0, lat0), rtol=1e-12)  # same two lines as Grid.ll2px

# --- how far does "north" turn across the sheet? ---
for name, xpix in (("left edge", 0.0), ("low", cx), ("right edge", float(g.w))):
    lon_a, lat_a = g.px2ll(xpix, cy)  # the place at this pixel
    x1, y1 = g.ll2px(lon_a, lat_a + 0.1)  # a point 0.1° further north
    tilt = np.degrees(np.arctan2(x1 - xpix, cy - y1))  # angle of "north" from straight up; + = leaning right
    print(f"north at the {name:10s} ({float(lon_a):6.1f}°E): {tilt:+5.1f}° from straight up")

# %% [markdown]
# **Putting a field on the grid.** ERA5 lives on a latitude-longitude grid; the poster needs a value at every pixel
# centre. `Grid.sample` does a **bilinear interpolation**: find the four grid points around the pixel, weight them by
# closeness. From scratch for one pixel, then the whole sheet at once:

# %% RUN :: Put the fields on the grid :: Bilinear interpolation for one pixel by hand, then the whole sheet.
T_da = pl.temperature.sel(time=np.datetime64(HOUR))  # kelvin, (latitude, longitude)
lon_p, lat_p = (float(v) for v in g.px2ll(cx - 300.5, cy - 200.5))  # the place under one pixel centre, up-left of the low
lats, lons = T_da.latitude.values, T_da.longitude.values  # both increasing
ia = int(np.searchsorted(lats, lat_p) - 1)  # index of the grid latitude just south of the place
io_ = int(np.searchsorted(lons, lon_p) - 1)  # index of the grid longitude just west of it
fy = (lat_p - lats[ia]) / (lats[ia + 1] - lats[ia])  # 0 at the southern row, 1 at the northern row
fx = (lon_p - lons[io_]) / (lons[io_ + 1] - lons[io_])  # 0 at the western column, 1 at the eastern column
v = T_da.values
south = v[ia, io_] * (1 - fx) + v[ia, io_ + 1] * fx  # blend west-east along the southern row
north = v[ia + 1, io_] * (1 - fx) + v[ia + 1, io_ + 1] * fx  # the same along the northern row
T_scratch = south * (1 - fy) + north * fy  # then blend south-north

T = g.sample(T_da, strict=False) - 273.15  # the whole sheet at once, kelvin -> °C (NaN outside the data box)
np.testing.assert_allclose(T_scratch - 273.15, T[int(cy - 201), int(cx - 301)], atol=2e-3)  # float32 rounding only
q = g.sample(pl.specific_humidity.sel(time=np.datetime64(HOUR)), strict=False) * 1000.0  # kg/kg -> g/kg
p = g.sample(msl.sel(time=np.datetime64(HOUR)), strict=False) / 100.0  # Pa -> hPa
print(f"T850 at that pixel: {T_scratch - 273.15:.2f} °C | on the sheet: T {np.nanmin(T):.1f}..{np.nanmax(T):.1f} °C, "
      f"q {np.nanmin(q):.1f}..{np.nanmax(q):.1f} g/kg, p {np.nanmin(p):.0f}..{np.nanmax(p):.0f} hPa")

# %% [markdown]
# ## 4 · Colour: two fills, each with a colour bar you can trust
# * **Temperature** uses `cmocean.balance`, a *diverging* map: two hues that meet in white. A diverging map needs a
#   meaningful middle, and here it has one: **0 °C, freezing**. The range is symmetric, −12 to +12 °C, so white is
#   exactly 0 °C and equal steps either side look equally strong.
# * **Moisture** uses `cmocean.deep` reversed, a *sequential* map (dark = dry, light green = moist), from 0 to 10 g/kg.
#   Humidity has no natural middle, so one hue ramp is right.
# * **No rainbow / jet.** Rainbow maps have bright bands that invent edges in smooth data, and they fail for
#   colour-blind readers. The cmocean maps are perceptually even.
#
# The colours are applied **with numpy, pixel by pixel** (`fill_layer`): value → 0..1 → colour. No resampling, so a
# colour on the poster is exactly the colour-bar colour of that pixel's value.

# %% RUN :: Colour the fills :: One temperature to its colour by hand, then both fill layers.
rings = lw.land_polys(g, pad_deg=10)  # Natural Earth coast as pixel polygons
# --- from scratch: the colour of one temperature ---
vmin, vmax = lw.T_RANGE  # -12, +12 °C
T_px = float(T[int(cy - 201), int(cx - 301)])  # the pixel sampled above
frac = np.clip((T_px - vmin) / (vmax - vmin), 0, 1)  # where the value sits in the range, 0..1
rgb_scratch = np.array(lw.T_CMAP(frac)[:3])  # look that fraction up in the colour map
t_fill = lw.fill_layer(g, T, lw.T_CMAP, *lw.T_RANGE, rings, "#0b1020", 0.6)  # the whole layer (+ a thin coast line)
np.testing.assert_allclose(rgb_scratch, t_fill[int(cy - 201), int(cx - 301)], atol=1e-6)
print(f"{T_px:.2f} °C -> fraction {frac:.3f} -> RGB {np.round(rgb_scratch, 3)}; 0 °C -> {np.round(lw.T_CMAP(0.5)[:3], 2)} (white)")
q_fill = lw.fill_layer(g, q, lw.Q_CMAP, *lw.Q_RANGE, rings, "#9fb4c8", 0.55)
show(u8(np.concatenate([t_fill[::4, ::4], q_fill[::4, ::4]], axis=1)), 900)

# %% [markdown]
# ## 5 · Line work: isobars, moisture contours, wind arrows
# Lines are what make overlaps useful (next section), so every lens that can sit on top of another needs a
# *line-work version* of its field, drawn on a transparent layer:
#
# * **Isobars** every 4 hPa (the standard spacing on surface charts), every 20 hPa bolder, labelled every 8 hPa.
#   Tightly packed isobars mean strong wind.
# * **Moisture contours** at 4, 6, 8 g/kg, dashed, on a lightly smoothed field so the lines are calm.
# * **Wind arrows**, one every 46 px (67 km), 2.1 px per m/s. ERA5 gives the wind as *u* (toward east) and *v*
#   (toward north). On this map east is not "right" away from the central meridian, so each arrow is turned by the
#   map's own east and north directions at its place. Below, from scratch for one arrow.

# %% RUN :: Line work :: One wind arrow turned to the map by hand, then isobars, moisture lines and arrows.
u_da = sfc["10m_u_component_of_wind"].sel(time=np.datetime64(HOUR))  # m/s toward east
v_da = sfc["10m_v_component_of_wind"].sel(time=np.datetime64(HOUR))  # m/s toward north
gx, gy = cx - 600.0, cy + 200.0  # one arrow position, 870 km west of the low (pixels)
wlon, wlat = (float(a) for a in g.px2ll(gx, gy))  # the place there
u1 = float(g.sample(u_da, np.array([wlon]), np.array([wlat]), strict=False)[0])  # wind toward east there
v1 = float(g.sample(v_da, np.array([wlon]), np.array([wlat]), strict=False)[0])  # wind toward north there
east = np.array(g.ll2px(wlon + 0.01, wlat)) - (gx, gy)  # the pixel step you make going a little east
east /= np.linalg.norm(east)  # ... as a unit vector (x right, y down)
north = np.array(g.ll2px(wlon, wlat + 0.01)) - (gx, gy)  # the same going a little north
north /= np.linalg.norm(north)
arrow = u1 * east + v1 * north  # the wind as a pixel vector: u along local east, v along local north
print(f"at {wlon:.1f}°E {wlat:.1f}°N: u = {u1:.1f}, v = {v1:.1f} m/s ({np.hypot(u1, v1):.1f} m/s). "
      f"Local east on the sheet = ({east[0]:.3f}, {east[1]:.3f}), so the arrow is ({arrow[0]:.1f}, {arrow[1]:.1f}) px-units, "
      f"not ({u1:.1f}, {-v1:.1f}).")
assert abs(east @ north) < 1e-3  # local east and north are at right angles on the sheet: the map is conformal
assert abs(np.hypot(*arrow) - np.hypot(u1, v1)) < 0.01  # so turning the arrow does not change its length

layers = lw.hour_layers(g, rings, sfc, pl, HOUR)  # t, q fills; ql moisture lines; pg chart ground; po isobars + arrows
print({k: v.shape for k, v in layers.items()})
ground = layers["pg"]  # the plain dark-blue chart ground of the pressure lens
a = layers["po"][..., 3:]  # the transparency of the line-work layer
chart = ground * (1 - a) + layers["po"][..., :3] * a  # lines over ground: what the pressure lens shows on its own
win = (slice(int(cy - 520), int(cy + 520)), slice(int(cx - 700), int(cx + 700)))  # a window round the low
show(u8(chart[win][::2, ::2]), 800)

# %% [markdown]
# ## 6 · The no-blend rule
# Now the three lenses, and the question from tutorial 1: what happens where they overlap?
#
# **If we blend (overlap = 0.5):** the temperature colour and the moisture colour are averaged. The result is a
# colour that is on *neither* colour bar. The cell below takes one pixel in the overlap and asks: "if a reader looks
# this blended colour up on the temperature bar, what temperature do they read?"
#
# **The rule for data fields (overlap = 0):** the lower lens **keeps its exact colours**; an upper lens contributes
# only its **line work** there. The overlap becomes a true overlay. Where all three lenses meet you see temperature
# as colour, moisture as dashed lines, pressure as isobars and the wind as arrows: a complete weather chart.
#
# That also fixes the **order**: the richest fill (temperature) lies lowest because it is the colour you see in every
# overlap; the pure line-work lens (pressure and wind) lies on top.

# %% RUN :: The no-blend rule :: Blended against exact overlaps, with the temperature a reader would read off each.
cen = lw.lens_centres(cx, cy)  # lens centres relative to the low
base = lw.poster_base(g, rings)  # the muted map outside the lenses: black sea, dark land, faint relief and graticule
exact = lw.make_lenses(layers, cen)  # overlap = 0 on every lens
mixed = lw.make_lenses(layers, cen)
for Ln in mixed:
    Ln.overlap = 0.5  # the city-poster look, WRONG for data
img_exact, img_mixed = lc.composite(base, exact), lc.composite(base, mixed)

# one pixel inside both the temperature lens and the moisture lens, away from any line
qx, qy = int(cen["t"][0] + 60), int(cen["q"][1] - 380)
T_true = float(T[qy, qx])
bar = np.array([lw.T_CMAP(f)[:3] for f in np.linspace(0, 1, 481)])  # the temperature colour bar in 0.05 °C steps
bar_T = np.linspace(*lw.T_RANGE, 481)


def read_off(rgb):  # the temperature whose bar colour is closest to a given colour
    return float(bar_T[np.argmin(((bar - rgb) ** 2).sum(1))])


print(f"true temperature at that pixel:        {T_true:+.1f} °C")
print(f"read off the exact (overlap 0) colour: {read_off(img_exact[qy, qx]):+.1f} °C")
print(f"read off the blended (0.5) colour:     {read_off(img_mixed[qy, qx]):+.1f} °C   <- the blend misleads the reader")
assert abs(read_off(img_exact[qy, qx]) - T_true) < 0.1  # exact colours still match the bar

mid = (slice(int(cy - 420), int(cy + 420)), slice(int(cx - 560), int(cx + 560)))  # where the three lenses meet
show(u8(np.concatenate([img_mixed[mid], np.zeros((840, 24, 3), np.float32), img_exact[mid]], axis=1)[::2, ::2]), 1000)
print("left: blended overlaps (colours match no colour bar) | right: the no-blend rule (fill below, lines above)")

# ## 8 · Why it looks the way it does
#
# | Choice | Reason |
# |---|---|
# | Lenses ride on the tracked low | all three look at the storm; the offsets put the warm sector in the temperature lens, the moist inflow in the moisture lens and the strongest pressure gradient in the pressure lens |
# | `overlap = 0` on every lens | the no-blend rule: a colour must match its colour bar everywhere |
# | Order: temperature, moisture, pressure & wind | lowest = the fill you see in overlaps; top = pure line work |
# | Diverging map centred on 0 °C; sequential map for humidity | the colour map follows the meaning of the numbers |
# | A colour bar or key inside every label block | each lens explains itself; no separate legend to hunt for |
# | Isobar labels on the poster only | at poster size 24-px labels are readable; in a video they would be too small, so the label block says "every 4 hPa" |
# | Scale bar with a note, graticule, no north arrow | on a conic map scale is true only near the standard parallels and north turns across the sheet |
# | "850 hPa" always explained as "1.5 km up" | the reader may not know pressure levels |
# | Base map nearly black with faint relief | it only has to say "this is the North Atlantic and Europe" |
#
# Two limits of this picture: 850-hPa values are extrapolated below ground over high mountains, and ERA5's 28-km
# grid smooths the sharpest gusts.

#
# **What this recipe makes.** The 41-second clip of the gallery shows Storm Ciarán on 1-2 November 2023 through three
# round lenses on one dark map of the north-east Atlantic: **temperature** about 1.5 km up, **moisture** there, and
# **sea-level pressure with the wind**. The lenses open one by one, sweep across the map, then follow the tracked low
# while one clock steps all three fields hour by hour.
#
# The clip is made in two parts:
#
# 1. **Python makes every picture** (this notebook, also on Google Colab): one PNG per field and hour on one pixel

# layers: the lenses follow the low hour by hour, without the sweep and without the moving wind streaks.
#
# **Data:** ERA5 reanalysis (Copernicus Climate Change Service / ECMWF), ETOPO 2022 relief (NOAA NCEI), Natural Earth

# %% [markdown]
# ## 3 · The lenses follow the low
# A lens is a **circular mask** on the common pixel grid. Three lenses of radius 180 px:
#
# * **pressure and wind** rides on the tracked low;
# * **temperature** sits 185 px to its west and a little north (the cold air behind the storm);
# * **moisture** swings round the low at a fixed distance, south-west of it and then due south (the moist air that
#   feeds the storm), as far as the bottom edge of the map allows.
#
# Where lenses overlap, `overlap = 0` (the **no-blend rule** for data fields): the lower lens keeps its exact colours,
# so they still match its colour bar, and the upper lens adds only its lines.

# %% RUN :: One hour :: Lens centres from the manifest, the lens rule, and the picture of one hour.
R = 180  # lens radius in map pixels
RIM = {"t": "#e8833a", "q": "#2aa198", "p": "#f4ecd2"}  # rim colours: orange, teal, warm white
MAP_H = man["h"]
base, ground = layer("ctx.png")[..., :3], layer("p.png")[..., :3]


def centres(i: int):
    """Centres (map pixels) of the temperature, moisture and pressure lenses at hour i."""
    px, py = man["low"][i]["x"], man["low"][i]["y"]  # the tracked low
    t = (px - 185.0, float(np.clip(py - 80.0, R + 6, MAP_H - R - 6)))
    dy = min(172.0, MAP_H - R - 6 - py)  # how far south of the low the moisture lens may sit
    q = (px - max(30.0**2, 176.0**2 - dy**2) ** 0.5, py + dy)
    return t, q, (px, py)


def map_picture(i: int, n_open: int = 3):
    """The map of hour i with the first ``n_open`` lenses, and those lenses."""
    t, q, p = centres(i)
    lenses = [lc.Lens(layer(f"t_{i:02d}.png"), *t, R, RIM["t"], overlap=0.0),
              lc.Lens(layer(f"q_{i:02d}.png"), *q, R, RIM["q"], over=layer(f"ql_{i:02d}.png"), overlap=0.0),
              lc.Lens(ground, *p, R, RIM["p"], over=layer(f"pl_{i:02d}.png"), overlap=0.0)][:n_open]
    return lc.composite(base, lenses), lenses

# ## 4 · A pure-Python approximation of the clip
# Each hour becomes one 1920 × 1080 page: the map of step 3 with rims and the **L**, the title, the date and the

# %% RUN :: The approximation :: Writes lens_map_python.mp4 and a GIF, and plays the clip.
MX, MY = 60, 196  # where the map sits on the page
MON = ["Jan", "Feb", "Mar", "Apr", "May", "Jun", "Jul", "Aug", "Sep", "Oct", "Nov", "Dec"]

       ("PRESSURE & WIND", "Motion · isobars every 4 hPa", RIM["p"]),
       ("MOISTURE", "Fuel · vapour 1.5 km up, 0 to 10 g/kg", RIM["q"])]


def page(i: int, n_open: int = 3) -> np.ndarray:
    """The whole 1920 x 1080 page of hour i as a float RGB picture."""
    img, lenses = map_picture(i, n_open)
    fig, ax = lc.canvas(1920, 1080, "#171f33")
    ax.imshow(img, extent=(MX, MX + man["w"], MY + man["h"], MY), interpolation="nearest", zorder=1)
    for L in lenses:  # rims; the map sits at (MX, MY) on the page
        ax.add_patch(__import__("matplotlib").patches.Circle((MX + L.cx, MY + L.cy), L.r, fill=False, ec=L.rim, lw=3.2, zorder=21))
    low = man["low"][i]
    if n_open == 3:
        lc.text(ax, MX + low["x"], MY + low["y"] + 12, "L", 40, "#f4ecd2", weight="bold", ha="center")
    lc.text(ax, 60, 96, "One storm, many ", 76, "#f4ecd2", family=lc.SERIF, weight="bold")
    lc.text(ax, 60, 160, "realities.", 76, "#e8833a", family=lc.SERIF, weight="bold", style="italic")
    iso = man["times"][i]
    lc.text(ax, 1262, 90, "Storm Ciarán", 52, "#f4ecd2", weight="bold")
    lc.text(ax, 1262, 146, f"{iso[11:13]} UTC · {int(iso[8:10])} {MON[int(iso[5:7]) - 1]} {iso[:4]}", 44, "#d8b23a")
    lc.text(ax, 1262, 200, f"low centre {low['hPa']:.0f} hPa", 44, "#e8ecf4")
    for k, (name, what, colour) in enumerate(KEY[:max(n_open, 1)] if n_open < 3 else KEY):
        y = 300 + 170 * k
        ax.plot([1238, 1238], [y - 40, y + 70], color=colour, lw=6, solid_capstyle="butt", zorder=30)
        lc.text(ax, 1262, y, name, 44, "#f4ecd2", weight="bold")
        lc.text(ax, 1262, y + 54, what, 34, colour, family=lc.SERIF, style="italic")
    lc.text(ax, 60, 866, "Data: ERA5 (Copernicus C3S / ECMWF) · ETOPO 2022 · Natural Earth · lens style after Fan Mo, #30DayMapChallenge 2026 Day 14", 30, "#9aa6bd")
    lc.text(ax, 60, 912, lc.AUTHOR, 30, "#f1ede4", weight="bold")
    return lc.grab(fig)[..., :3]


FPS = 12
size = (960, 540) if QUICK else (1920, 1080)


def fit(a: np.ndarray) -> np.ndarray:
    """The page at the output size."""
    if a.shape[1] == size[0]:
        return a
    return np.asarray(Image.fromarray((np.clip(a, 0, 1) * 255 + 0.5).astype(np.uint8)).resize(size, Image.LANCZOS), np.float32) / 255.0


clip = OUT / "lens_map_python.mp4"
writer = an.Writer(clip, size, fps=FPS)
for n_open in (0, 1, 2):  # the lenses open one after the other on the first hour
    writer.add(fit(page(0, n_open)), repeat=FPS // 2)
for i in range(LAST_HOUR + 1):  # then one page per hour
    writer.add(fit(page(i)), repeat=max(1, int(round(SECONDS_PER_HOUR * FPS))))
writer.add(fit(page(LAST_HOUR)), repeat=2 * FPS)  # hold the last hour
writer.close()
gif = an.to_gif(clip, width=480, fps=6)
print(f"{clip.name}: {writer.n} frames, {writer.n / FPS:.0f} s, {clip.stat().st_size / 1e6:.1f} MB | {gif.name}: {gif.stat().st_size / 1e6:.1f} MB")
nb.video(clip, width=960)

Glass-pane globe stack

    
A relief globe with six glass panes in front of it. Each pane shows the same round patch of the Earth (India, Bangladesh and the Bay of Bengal) at the same moment of one weather forecast, each with a different quantity: temperature, sea-level pressure with isobars, wind, precipitable water, cloud cover and rain rate. Read it from the left: the globe with the region facing you, then the panes numbered 1 to 6, then one colour bar per number. The panes are not at physical heights: they are six maps of one patch, pulled apart. The second video is the Remotion version: five panes of the whole hemisphere over the North Atlantic.

Steps to make it

    
  1. Load six fields of one GFS run: the small file shipped with the repository, or live and anonymous from dynamical.org (SOURCE = "live", needs icechunk and zarr; falls back to the shipped file).
  2. Make the round view of one field: an orthographic projection written by hand, read back onto the data grid.
  3. Draw the six pane pictures: one colour ramp and one opacity rule per quantity, isobars every 4 hPa, the coastline.
  4. Make the globe's skin: shaded ETOPO 2022 relief with the coast drawn in.
  5. Put globe and panes in 3-D with a small ray caster in numpy.
  6. Add the legend with numbered chips, the clock, the timeline and the credits; save the poster.
  7. For the video, move the camera and the panes along a few keyframes while the forecast steps, and encode with ffmpeg.
  8. For the Remotion version (Node.js on your own machine): write the relief, 40 pane pictures and a manifest from Python, then render the project in remotion/glass_stack/.

# %% [markdown]
# # Glass-pane globe stack
#
# **The picture.** A relief globe with six glass panes standing in front of it. Every pane shows the same round
# patch of the Earth (the cap of 21° around 21°N 87°E: India, Bangladesh, the Bay of Bengal) at the same moment of
# one weather forecast, each with a different quantity: temperature, sea-level pressure, wind, precipitable water,
# cloud cover and rain rate. The panes are pulled apart along the line of sight to that patch, so each can be seen,
# and they line up with the globe behind them.
#
# **How to read it.** Left: the globe with the region turned towards you. In front of it, fanned to the right: the
# panes, numbered 1 (nearest the globe) to 6. Right: what each numbered pane shows, with its colour bar. Bottom: the
# lead time, the valid time in UTC and in Indian Standard Time, the place of that time on the five-day timeline, and
# the sources. The panes are **not** at physical heights: they are six maps of one patch, pulled apart.
#
# **The data.** NOAA GFS forecast, 0.25°, run of 16 November 2026 18 UTC, read from
# [dynamical.org](https://dynamical.org) (CC BY 4.0). Relief: ETOPO 2022 (NOAA NCEI). Coastlines: Natural Earth.
#
# Steps: 1 data → 2 the round view of one field → 3 six pane pictures → 4 the globe's skin → 5 globe and
# panes in 3-D → 6 the finished poster → 7 the animation → 8 the inputs of the Remotion version.

# %% [markdown]
# ## Settings
# Everything you may want to change is in this one cell. The checks at the bottom **stop** the notebook with a plain
# message if a setting cannot work, before anything slow starts.
#
# `MODE = "FAST"` (the default, about two minutes; right for Google Colab) writes the poster at 1920 × 1080 px and a
# short preview clip of the animation at 960 × 540 px. `MODE = "FULL"` writes the poster at 3840 × 2160 px and the
# whole animation (16 s, 1280 × 720 px, 24 frames a second; several minutes).
#
# `SOURCE = "shipped"` (the default) reads the small data file that comes with the repository: no network to
# dynamical.org is needed. `SOURCE = "live"` reads the run `RUN` straight from dynamical.org, anonymously (first
# `pip install icechunk zarr`; about 35 MB, about a minute); if that read fails for any reason, the shipped file is
# used and a line says so.

# %%
import os
import sys

MODE = "FULL" if "--full" in sys.argv else os.environ.get("GIS_MODE", "FAST")   # "FAST" (preview) or "FULL" (poster size, whole animation)
OUT_DIR = os.environ.get("GIS_OUT", "")          # output folder; "" = /content/out on Google Colab, ./out anywhere else
SOURCE = os.environ.get("GIS_SOURCE", "shipped")  # "shipped" (the file of the repository) or "live" (dynamical.org)
RUN = "2026-11-16T18:00"                         # with SOURCE = "live": the GFS run, hour 00, 06, 12 or 18 UTC; None = the newest complete run
LEAD = 66                                        # the lead time of the poster in hours: a multiple of 6 from 6 to 102
CAP = dict(lat0=21.0, lon0=87.0, rad_deg=21.0)   # the cap every pane shows: centre and angular radius in degrees

import datetime as dt

from gismaps import nb                           # helpers: show(), video(), STOP checks, PASS / FAIL

nb.stop_unless(MODE in ("FAST", "FULL"), f"MODE = {MODE!r} must be FAST or FULL")
nb.stop_unless(SOURCE in ("shipped", "live"), f"SOURCE = {SOURCE!r} must be shipped or live")
nb.stop_unless(LEAD in range(6, 103, 6), f"LEAD = {LEAD} must be a multiple of 6 from 6 to 102 (cloud and rain are averages: there is no value at 0)")
if SOURCE == "live" and RUN is not None:
    try:
        _run = dt.datetime.fromisoformat(RUN)
    except (TypeError, ValueError):
        _run = None
    nb.stop_unless(_run is not None and _run.hour in (0, 6, 12, 18) and _run.minute == 0,
                   f"RUN = {RUN!r} must look like '2026-11-16T18:00' with hour 00, 06, 12 or 18 (or be None for the newest run)")
WORKER = bool(os.environ.get("GIS_PART"))        # (set only in the frame workers of the parallel FULL render: they skip the extras)
POSTER_SCALE = 2.0 if MODE == "FULL" and not WORKER else 1.0   # the design size is 1920 x 1080; the poster is saved at this multiple
OUT = nb.out_dir(OUT_DIR)
print(f"settings OK | mode: {MODE} | data: {SOURCE} | output folder: {OUT} | poster {int(1920 * POSTER_SCALE)} x {int(1080 * POSTER_SCALE)} px")

# ## 1 · The data
# Six fields of one forecast run on the box 0-44°N, 62-112°E at 0.25°, every 6 hours from +6 h to +102 h:
# temperature at 2 m, sea-level pressure, wind speed at 10 m, precipitable water (the water vapour of the whole
# column of air, as the depth of rain it would make), total cloud cover, and the precipitation rate averaged over
# the 6 hours before each lead time. The shipped file keeps them as 16-bit numbers (2 MB).

# %%
import numpy as np
import matplotlib.pyplot as plt

from gismaps.glass import gfs, ortho, panes, render        # the code of this recipe
from gismaps.glass.stack import GlassStack
from gismaps.styles import common as C

ds = gfs.region(SOURCE, RUN)                     # dims (lead, latitude, longitude)
RUN = ds.attrs["run"]
print("run:", RUN, "UTC |", dict(ds.sizes), "|", ds.attrs["credit"])
for k in ds.data_vars:
    a = ds[k].sel(lead=LEAD)
    print(f"  {k:5s} at +{LEAD} h: {float(a.min()):8.1f} to {float(a.max()):8.1f} {a.attrs['units']}")

# %% [markdown]
# ## 2 · The round view of one field
# Stand far away, straight above the centre of the cap: what you see is a disc, the **orthographic projection**.
# Each pane shows exactly that view, which is why the panes line up with the globe behind them. To make the
# picture we go backwards: for every pixel of the disc, `ortho.inverse` gives the place it shows, and
# `ortho.sample` reads the field there (bilinear). Going backwards leaves no holes. East is to the right and north
# is up, as seen from outside the globe.

# %%
F = panes.fields(ds, LEAD)                       # the six maps of the poster's lead time (+ a smoothed pressure for the isobars)
lat_px, lon_px, inside, _ = ortho.disc(360, **CAP)          # the place each pixel of a 360 x 360 pane shows
pw = F["pwat"]
disc = np.where(inside, ortho.sample(pw.values, pw.latitude.values, pw.longitude.values, lat_px, lon_px), np.nan)

th = np.linspace(0, 2 * np.pi, 200)              # the edge of the cap, drawn on the flat grid
edge_lat, edge_lon = ortho.inverse(np.cos(th), np.sin(th), CAP["lat0"], CAP["lon0"], np.sin(np.radians(CAP["rad_deg"])))
fig, axs = plt.subplots(1, 2, figsize=(11, 4.6))
axs[0].pcolormesh(pw.longitude, pw.latitude, pw, cmap=panes.ramp("pwat"), vmin=0, vmax=60, shading="nearest")
axs[0].plot(edge_lon, edge_lat, color=panes.K["amber"], lw=1.8)
axs[0].set_title("the grid as stored: latitude × longitude"); axs[0].set_xlabel("longitude (°E)"); axs[0].set_ylabel("latitude (°N)")
im = axs[1].imshow(disc, cmap=panes.ramp("pwat"), vmin=0, vmax=60, extent=(-1, 1, -1, 1))
axs[1].set_title("the same numbers on the disc (orthographic)"); axs[1].set_xlabel("u (east →)"); axs[1].set_ylabel("v (north ↑)")
fig.colorbar(im, ax=axs, shrink=0.85, pad=0.02, label="precipitable water (kg m⁻²)")
plt.show()

# %% [markdown]
# ## 3 · Six pane pictures
# A pane picture has four numbers per pixel: red, green, blue and opacity. `panes.pane` colours the disc with one
# ramp per quantity and chooses the opacity; then it draws lines on top (isobars every 4 hPa, the coastline), each
# projected with `ortho.forward`. The rules, nearest the globe first:
#
# 1. temperature: a two-sided ramp with white at 0 °C;
# 2. pressure: a quiet blue-grey fill, the isobars carry the information (drawn from a lightly smoothed copy,
#    because stored pressure comes in steps of 0.64 hPa);
# 3. wind speed and 4. precipitable water: one hue each, dark to bright;
# 5. cloud: the opacity grows with the cloud cover, so clear sky is clear glass;
# 6. rain rate: a logarithmic scale, fully clear below 0.2 mm per hour.

# %%
coast = panes.coast_lines("50m")                 # Natural Earth coastline (a small download the first time)
six = panes.six_panes(F, CAP, coast, n=480)      # six dictionaries: the picture "tex" (480 x 480 x 4) and what the legend needs
fig, axs = plt.subplots(2, 3, figsize=(11, 7.4))
for a, P in zip(axs.ravel(), six):
    a.set_facecolor(panes.K["bg"]); a.imshow(P["tex"], extent=(-1, 1, -1, 1))
    a.set_title(f"{P['title']} ({P['unit']})"); a.set_xticks([]); a.set_yticks([])
plt.tight_layout(); plt.show()

# %% [markdown]
# ## 4 · The globe's skin
# The globe needs one picture that wraps around it: a map in plain latitude × longitude (row 0 = 90°N, column 0 =
# 180°W). `panes.relief_texture` builds it from ETOPO 2022 heights: light clay for land, slate blue for sea, shaded
# as if lit from the north-west so that mountains show (the shading is exaggerated), with the coastline drawn in.

# %%
elev = gfs.relief()                              # heights in metres on a 10 arc-minute grid
skin = panes.relief_texture(elev, coast)         # 1440 x 2880 x 3, values 0..1
plt.figure(figsize=(10, 5)); plt.imshow(skin, extent=(-180, 180, -90, 90)); plt.xlabel("longitude (°E)"); plt.ylabel("latitude (°N)")
plt.show()

# %% [markdown]
# ## 5 · Globe and panes in 3-D
# `render.render_stack` is a small ray caster. For every pixel it follows a straight line from the eye and asks what
# the line hits: the globe (a quadratic equation) and each pane (one division: where the line meets the pane's
# plane). The globe is painted first, then the panes from the nearest to the globe outwards, each laid over the
# picture with its opacity. Rendering at twice the size and shrinking (`ss=2`) smooths every edge.
#
# The camera sits 42° west of the stack axis and 15° above it, so the panes fan out to the right of the globe.
# The panes are spaced 0.9 × the disc radius apart, enough for a strip of every pane to be seen.

# %%
stack = GlassStack(ds, CAP, place="India and Bangladesh", local=(5.5, "IST"), coast=coast, elev=elev, skin=skin)
cam = stack.fan_camera((1920, 1080))             # the fanned view (az = -42, el = 15)
bare = stack.render(six, cam, ss=1)              # globe and six panes, no labels yet
plt.figure(figsize=(11, 6.2)); plt.imshow(bare); plt.axis("off"); plt.show()

# %% [markdown]
# ## 6 · The finished poster
# `stack.poster` renders the same view with smooth edges and adds what a picture of data needs: a top strap with
# the title, a legend column with one numbered row per pane (the same number sits on a chip at the pane's upper
# right corner, found with `render.project`), the lead time with the valid time in UTC and local time, a timeline,
# and the credits.
#
# What to look for: the closed isobars on pane 2 over the south-west Bay of Bengal are a **low** (a region of low
# pressure that air spirals into). On the panes in front of it you find its bright wind, its plume of precipitable
# water, its cloud shield and its rain: one system, six views.

# %%
poster = stack.poster(OUT / "glass_stack.png", lead=LEAD, scale=POSTER_SCALE)
nb.show(poster)

# %% [markdown]
# ## 7 · The animation
# The film is one function of time, `stack.film_state(t)`: it returns the camera, the gap between the panes, each
# pane's opacity and lift, and the lead time shown, each as an eased blend between keyframe values. In 16 seconds:
# the globe glides towards the region (0-3 s), the panes fan out (3-5 s), the precipitable-water pane is lifted
# with an amber edge while the others dim (6-9 s), the forecast clock runs from +6 h to +102 h (9-14 s; the pane
# pictures are made every 6 hours and cross-faded in between), and the panes close up on the globe (14-16 s).

# %%
if MODE == "FULL":                               # the whole animation: 384 frames, 1280 x 720 px
    movie = stack.animate(OUT / "glass_stack.mp4", OUT / "frames_glass")
else:                                            # a short preview: every 4th frame, 960 x 540 px, 8 frames a second
    movie = C.preview(stack.animate, OUT / "glass_stack_preview.mp4", OUT / "frames_glass", thin=4, scale=0.75, fps=8)
nb.video(movie)

# ## 8 · The inputs of the Remotion version

# `remotion/glass_stack` of the repository. This cell writes everything that project loads: the globe's skin, 40

if WORKER:

else:

size = (int(1920 * POSTER_SCALE), int(1080 * POSTER_SCALE))

]
if low is not None:
